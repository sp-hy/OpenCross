# Battle element / tech / summon effects: pipeline, files, overlays

Every battle element (spell, tech, summon, trap, boss death, background effect) plays an effect made of a triple of archive files: a texture upload (`.ctd`), a data pack (`.prd`: particle emitters, a timed sequence, camera tracks, sound, meshes, anim packs) and a small code overlay (`.prg`). This document covers how an element id reaches those files, the on-disk layouts, the sequence and emitter opcodes, the overlay families that carry code, and how OpenCross plays all of it (generic player, bespoke overlay ports, known deviations). Related: `room_effects.md` (the 0x0A emitter and 0x10 sequence engine is the same code), `battle_data.md` (pgdat), `model.md` (anim packs). Tool: `python -I tools/py/cc_effects.py [--game DIR] map [--all] | info <file|eid> | validate | stats`.

## 1. Summary
* Every battle effect is a **triple of files in consecutive archive slots** `(egfx .ctd, eins .prd, overlay .prg)`, selected by the 16-bit **effect id** (`eid`) at `pgdat.bin` +0x10. 537 slots hold real files; 504 are referenced by the 527 element records.
* The eins `.prd` is a DRP holding particle emitters (type 0x0A, 14059), a timed **sequence** (type 0x10, 2031), camera tracks (0x0C), AKAO sound sequences (0x16), sprite sheets / meshes / TIMs and anim packs. It is the same engine as the field-room effects.
* The `.prg` is a small overlay. 393 of 537 slots (402 of 526 elements) use a 372-480 byte stock host (`stdtech0/1`, `stdmag0`, `magtest`) that only does setup; those effects are pure data. The other 89 overlays (144 slots) are bespoke programs (section 5.4).
* `ENVMAP`, `LUSTER`, `sin-x`, `sin-v` found in the stock hosts are labels of a debug-build tool, not drawing commands (section 5.3).
* About three quarters of the elements play from a generic emitter/sequence player; the rest (the hand-coded black spells, boss deaths, several summons) need per-overlay ports (section 8).

## 2. Pipeline: element -> files -> run
1. **Element record** (`battle/data/pgdat.bin`, 527 x 0x2C bytes, id = index): `u16 @0x10` = `eid`. 526 records have one; element 0 has 0. Values 4..542; 504 distinct. Shared: 6 eids serve 28 elements (eid 396 = elements 108,109,111,112,114,115,117,118,120,121,123,124; eid 395 = 110,113,116,119,122,125; eid 32 = 1,127,134,135; 421 = 150,156; 414 = 151,157; 370 = 327,410). 33 slots are used by no element (13 traps, 7 bg, 6 summon, 4 monster, 2 tech, 1 ripple): battle scripts, death handling or summon code trigger them.
2. **Queue**: the acting unit's control block carries `eid`, written when the action is resolved: the element record's `eid`, unless an element trap catches the cast (it fizzles), when it is the trap pack of the element's colour (Caught casts, section 6). A double or triple tech copies the word to every participant, a cancelled command clears it. Nothing else writes it, so a cast never starts a slot that no element names and that is not one of the twelve trap packs (eid 142). When the acting unit reaches its effect state the engine starts effect `eid - 1`.
3. **Slot -> files**: battle effect files live in directory 0xB (first file id 4323). With `p = eid - 1` the files are local indices `3p+2`, `3p+3`, `3p+4`; as an absolute `cdrom.fnd` index (64-byte path records) that is `4322 + 3*eid + {0,1,2}` = **ctd, prd, prg**. Disc 2 (`cdrom2.fnd`) fills 28 slots that are dummy on disc 1 (Time Devourer `lasbos*`, `bg_86..99`, Dragon deaths, `df_eye/hadou`, ...) and swaps slot 378's overlay (`hinsi` -> `bossde`). `eid 1` = `bttim.ctd/.ltd` + `magtest.prg` is the **null effect**: used when the prd is
   < 0x40 bytes (a dummy slot, 24-byte `dummy.dat`) or the overlay is empty (the loader falls back to slot 1).
   Irregular slots: 1, 15, 16, 28 (holding `bttim`, summon `st_0N.mtc` / `wave0320.dat` / `mthun.prd`, `battle/bg/kamei`).
4. **Load**: (a) a ctd larger than 0x100 bytes is streamed into VRAM sector by sector; (b) the prd is read into a heap block and its DRP entries are registered; (c) the overlay is read to its fixed load address.
5. **Run**: the overlay entry is called with `cmd 0` (init), `1` (per frame), `2` (exit). Init of the stock hosts auto-starts the type-0x10 sequence named `main` (or `own` when caster == target).
6. **Sequence executor** (one task per sequence; the step rules are under **Timeline start** and **Timeline step**, section 9): reads ops, adds each op's wait (`u16 @+2`) to a countdown, handles flow ops itself (0x21 end, 0x42, 0x4D, 0x4E, 0x50, 0x67, 0x7A, 0x23 camera group) and forwards the rest to the op handler. If an overlay is resident it gets `(op, record)` first; every overlay forwards unknown ops to the stock handler, so an unknown op is a no-op.
7. **Teardown**: op 0x41 / overlay exit (cmd 2) frees the resource block and the afterimage buffer.
8. **Resident battle data**: `battle/battle.prd` is loaded at battle start and registered like any drp (its nested drps `miya` / `chih` / `tana` / `sato` are linked entry by entry; its TIMs go to VRAM at once). The element packs name its sheets (`b28`, `64ke`, `smok`, `kona`, `tam4`, `hite` ...: 143 packs) and meshes (`maru`, `wa0`, `sank`, `son1` ...: 81 packs) without holding them, and 44 packs' own mesh faces sample its texture pages (x 768..1023). The registry is searched pack first. The field's `effect/particle.prd` is not part of the battle VRAM (its TIMs overwrote egfx regions). OpenCross: `FxResident` (`BattleFxLibrary::load_resident`).

## 3. The eins `.prd` (DRP)
All 527 parse. Entry types over the 537 slot files:

| type | n | meaning |
|---|---|---|
| 0x0A | 14059 | particle emitter; identical engine and bytecode to `room_effects.md`; all parse with the room op table, no unknown op |
| 0x10 | 2031 | sequence (3.1); every file has `main`, some `own` / `loop`; framing identical to rooms but ~100 ops instead of 11 |
| 0x0C | 2771 | **camera track** played by op 0x23 by name: `u32 flags, u16 duration, u16 ease mode, u32 w8, u8 ref[4], u32 key count` then 20-byte keys (`u32, s16 eye xyz, s16 H, s16 target xyz, s16 roll`), i.e. `20 + 20 n` bytes (60 for the common 2-key shot); eye and target are relative to the frame of the `ref` anchors. Full layout and rules: `battle_stage.md` 6 and section 9 here. |
| 0x16 | 667 | **AKAO sound sequence** (`41 4B 41 4F`), played by op 0x4C |
| 0x05 | 506 | `wave`: sample bank for those AKAO sequences (20-41 KB) |
| 0x02 | 4056 | meshes (effect solids: rings, cones, beams; 2460 unique, `mar1/wak1/wakk/mar0` in ~50 files each) |
| 0x03 / 0x04 | 1198 / 1294 | timinfo sprite sheets / TIMs (as in rooms) |
| 0x19 | 323 | `tech`: cpt of animations (frame count, flag bits per joint, framePtr[]; `model.md`) for the caster(s) |
| 0x1A | 409 | `main` (cpt, 1 anim, small) and `dama` (3612 bytes, 6 blocks, byte-identical in 44 files: shared hit/damage-reaction template) |
| 0x0B / 0x18 / 0x01 / 0x07 / 0x15 / 0x24 / 0x25 | 44/54/14/4/6/1/5 | mdl, curve/path (looked up by emitter ops 3D/3E), nested drp, misc |

### 3.1 Sequence ops in battle
Header 0x14 bytes; op word `op = w & 0x1FF`, `len = (w>>9)&0x3F`, bit 15 = indirect pointer; `u16 @+2` = frames to wait after the op; all lengths are 8/12/16/20/24/28. The record name (4 chars) is at `+12` for 0x22/0x23/0x2F/0x2A/0x4C. Histogram over the 2031 sequences: START_EMITTER 8642, CAMERA 2505, RAMP_LEVEL 1503, FADE_IN 1405, CHILD_SEQ 1165, SCREEN_FLASH 894, SFX_BY_NAME 414, TASK2E 640, then 80 rarer ops. Op groups:
* **spawn**: 0x22 emitter, 0x2F child sequence, 0x55/0x5A emitter stop/kill, 0x4E loop label.
* **camera/screen**: 0x23 camera record, 0x28/0x29 controller rumble (not shake), 0x2E/0x2A screen shake, 0x2A colour matrix (type 0x11 entry), 0x2B/0x2C screen colour layers 0 / 1 (the tool's "fade in/out"), 0x2D depth-cue (fog) ramp, 0x3E/0x3F/0x40 screen copy warp, 0x24/0x6C depth cue on/off, 0x65 ambient colour fade, 0x6D/0x6E ground draw-order bias ramp (to s16 @+8 over s16 @+4 ticks) / reset to 100, 0x26/0x27 and 0x36-0x3D stage layers (section 9), 0x56 render flag (slow motion, section 9). The `SEQ_OPS` labels of the tool (SCREEN_FLASH, SCREEN_HOLD_ON, FX_LAYER*) are only tags; section 9 holds the rules.
* **actors**: 0x30-0x35, 0x5B-0x5E, 0x61-0x64, 0x68/0x69, 0x6F-0x72, 0x77/0x78 show/hide party / enemy / all; 0x43-0x46 / 0x4F / 0x57 model brightness (0x43/0x45 re-arm the model's anim script at entry `arg + 0x80`); 0x47/0x48 damage call (CallDamage of the battle overlay, 0x47 = one enemy, 0x48 = all enemies); 0x58 model colour fade; 0x74-0x76 model flags / facing.
* **sound**: 0x4C AKAO by name (the pack's type-0x16 entry; args: `s16@+16` volume, `s16@+18` pan, `u32@+20` mask; all 409 uses are 24 bytes with volume 0x7F, pan 0x80, mask 0); 0x51 SFX id (`s16@+8` id, `u32@+12` mask, `u8@+11` pan, `u8@+10` volume); 0x54 music-volume fade to `s16@+8 & 0x7F` over `s16@+4` frames (the same fade as the cast's own duck to 0x66 over 0x6D frames and restore to 0x7F over 0x60 at the effect end; 21 packs: the summons, Ultranova, the boss deaths, e.g. Salamander 96 over 56, the dragon deaths and lasdes3 0 over 247 / 300). There is no stop-sound op: a closed pack cuts its sounds.
* **flow** (executor): 0x21 end (the task ends once the op's own wait has run out), 0x42 wait CD idle, 0x4D next-target loop (a served loop returns with wait 0 and the next tick overshoots it, so a later pass is one tick shorter than the first), 0x50 wait actor flag, 0x67 yield (wait := 1 whatever the op's wait), 0x7A wait while a song change runs (the fade-out of 16 frames, the read and start of the new song; OpenCross starts a song at once, so the op never stalls; its only users, lasdes2's `main` and `msta`, come 390 and 1629 ticks after the op 0x101 that asked for the song, long after the change has finished); 0x53 / 0x52 a hold counter on the battle's continuation after the effect (0x53 adds a hold, 0x52 releases one on the next frame; 0x52 alone in 8 packs: wipeoff, godhand, Pip's six form changes).

Ops with no case in the stock handler are overlay-private: **0x100-0x10D** (lasbos 0x100-0x107, lasdes2 up to 0x10D, most others 0x100/0x101) and **0x180-0x184** (the mesh-walker family, 5.4: start / progress / end / hide). The tool's `SEQ_OPS` table lists every op. 0x25 has no case (no-op); 0x24-0x27, 0x36-0x3D and 0x59 are specified in section 9; 0x6A is a CD load of `bttim.ltd` back into the shared VRAM (after a pack that overwrote it; it also adds a 0x53 hold) and shows nothing. OpenCross carries out 0x28 / 0x29 (pad rumble) and 0x54 (`BattleAudio::fade_music`); 0x52 / 0x53 / 0x6A have nothing to do: every pack owns its textures and the effect end is `BattleFxRun::done()`.

### 3.2 Emitters
Same 0x0A header, op table and spawner as rooms. Battle usage shifts: sprite type 3 (timinfo sheet) or type 14 (a type-0x02 mesh; also 15, 17, 19, 20, 21 of section 9), `ON_DEATH_SPAWN` (0x33) chains, and the extended-object ops are common: **7955 of 14059 emitters (57%) use at least one of 0x35, 0x36, 0x37, 0x3D, 0x3E, 0x3F, 0x40, 0x48, 0x49** (rooms: ~410 uses in 5437 emitters). Section 7 specifies them.

**Damage-number emitters**: `battle.prd` miya `damv` / `gurv` / `gaiv` (flight, op 0x38 time-reverse, blend 5, flags 0x0300000x = view space), `dam1` (rest, life 34, blend 0) and `dam2` (fade, life 26, blend 5) carry the `tana/numf` digits (frame = digit + 1, 11 = "miss!"). The chain and anchor rule are in `battle_numbers.h`.

## 4. The egfx `.ctd` (264 files, 2-139 sectors)
A sequence of sections; each = 1 header sector + N data sectors (2048 B). Header (checked on all 264 files):
```
u32 type (0x1200 | 0x1201)   u16 x, y, dx, dy (VRAM rect origin = (x+dx, y+dy))   u16 width in 16-bit words   u16 rows per sector
u16 1   u16 sector count   u32 sections in file (@+20)   u32 sector count (@+24)   u16 rows[] (@+28)
```
Data are raw 16-bit VRAM rows (4bpp/8bpp pixels and CLUT rows). Example `tech/3dan.ctd` (49 sectors): 4 CLUT strips (type 0x1201) at (256,226..234) and (320,234), then 5 pixel blocks (type 0x1200) at (448,384) 128x128 words, (640,384), (704,256), (760,256), (744,464). `cc_effects.py validate` checks every file ends on a section boundary. 265 of 537 slots have no ctd (dummy): those effects use only the shared battle textures.

**The effect CLUT strip keeps whatever was written last.** VRAM rows 224..239 at x 256 hold the effect CLUTs. Apart from a pack's egfx and `battle.prd`, these write there, and nothing clears the strip at a battle start or between casts:
* the title screen: `title.ltd` (the same palettes as `map/mapbin/opening.ctd`, the only room `.ctd` with a CLUT at (256, 239));
* menu and other non-battle screens (palettes not traced to a file);
* the results screen: the party's `battle/face/pNN.tim` palettes go to rows 237..239 and stay into the next field and battle;
* a weapon attack: the attacker's `at0.prd` TIMs are uploaded when the attack starts. Nine models carry one at (256, 239): `selju2`, `sel_yam2`, `gren1`, `gren2`, `farga`, `jakotu`, `kabuo`, `pierre` and `steena` (TIM `wind`, a green ramp). Serge's set also fills rows 230..233 and 235..237 (`wht0` `oto2` `dark` `cut0` `denk` `magu` `ranc`);
* the egfx of 151 effect slots fill row 239.

A mesh face drawn through a row that its own pack does not fill therefore shows what the last writer left. Three stock-host packs do this: 36shu (eid 49, Meteorite) `en02` through row 239 (4 bpp; it tints the meteor), t59ufo (eid 205) through rows 227..229 and 233..235, which only the summon's own `59ufo.ctd` fills and a caught cast does not load, and the unreachable slot 142 (section 5.2). OpenCross builds each pack's VRAM from its egfx and `battle.prd` only, so those faces stay transparent (`ocbattle fx-audit`, column `unloaded_clut_tris`).

## 5. Overlays
### 5.1 Shell
The overlay entry `(cmd, arg)`: `0` init, `1` tick, `2` exit, `0x100/0x101` (stock hosts) no-op, everything else goes to the stock op handler. 93 distinct overlay files serve effects (of 105 overlay folders), 228 B-28 KB, 4-31 functions each.

### 5.2 Stock hosts: `stdtech0` (261 slots), `stdmag0` (130), `stdtech1` (2), `magtest` (the null effect, slot 1, plus 1 slot)
Init: register the debug label (5.3), start `main` / `own`, allocate and chain the **afterimage buffer** (400 x 0x28-byte entries; used for weapon / limb trails), then set every party model's brightness to 0x80 for the `main` anim (`type 0x1A 'main'`). Exit frees the buffer. `stdmag0` is the same minus the brightness loop. An enemy's magic charge also starts the casting monster's own `mag<k>` camera timeline from its model's S6 DRP; it is a camera shot, not an effect sequence. One slot (eid 142, `hensin.prd` reused with `stdtech0`) carries ops 0x180-0x183 that nothing consumes: no-op. No element names that slot and no cast reaches it (section 2); Dopplegang plays the same pack through eid 11 and the hensin overlay. Slot 142 has no egfx: the pack's mesh faces name CLUT rows (256, 235..239) and 8 bpp pages at x 576..767 that only `hensin.ctd` (eid 11) fills. Started anyway on the PS1 (an element's eid word patched in memory), the meshes draw with whatever VRAM holds there, the CLUT rows the field room left and the battle transition's screen copy. No stock host has a private op, so `ocbattle fx-audit` does not count them under one.

OpenCross behaviour of the generic host (`BattleView::fx_begin`):
* **Init tail** (`stdtech0` and `soidash`; `stdmag0` / `stdtech1` have none): when the pack registered a type-0x1A `main`, the acting model gets entry +0xC = 0x80 and its anim script runs entry 0, variant 0 of the pack's own atk table (`start_script(caster, pack.anim, 0, 0, kRelease)`). That script moves the caster (GetPos, PosMoveT, VecMoveT, GetVec, OvalMoveS), starts the pack timeline `0000` and calls the targets' reactions (`fx_react`, variant 7 of the same table), whose CallDamage lands the hit. A pack with such a script or with sequence ops 0x44 / 0x46 gets no 4-tick pre-scheduled hit. The pack ends with its non-loop sequences (all emitter objects freed at once), then every unit is reset (shadow bit, model state, idle). Four packs are only such a script (a type-0x1A `main`, no `main` sequence, no emitter): `kill` (element 349, Solt and Peppor's scenes 402 / 425; the camera `cam0` and sound `se00` are the caster model's own), `comebigi` (452, the Pterodact pair, scenes 293 297-301 421 476; clips `tech` / `tec1` and the timeline `0000`), `konsin` (335, scene 477) and `bre_roza` (no element); they play like any other (`BattleFxLibrary::get` keeps a pack with a `main` table) and last as long as the caster's script.
* **Re-arming**: a script arm only restarts the model's anmseq (entry, counter 0; the first step runs later in the unit pass). The host init arms before the pack's `main` runs its t0 ops; a `main` that starts with op 0x45 / 0x43 re-arms the same script, so the caster's script runs once. `fx_begin` skips the host-init arm for a caster whose script a t0 pack op already armed (`fx_armed_at_start_`); packs whose `main` has no t0 op 0x45 (461 `sid_*`, PC techs) are unchanged.
* **Cut intro**: the `pli*` party intro ends with op 0x3F (clears the camera warp). The dev cast path (`ocbattleview --cast / --weapon`) cuts the intro after 8 ticks and clears the warp as the retail intro end does.
* **Type-0x19 entries**: a tech pack's `tech` (or `tec1`..`tec5`) entry is an external anim pack (`model.md`; guill_1 = 2 clips, 60 + 30 frames). It hangs on the caster of that acting-list index (any other name: on every caster and target), so the `main` script's SetAnim `0x80 + k` plays the pack's own clips. Ported: `FxPack::clip_packs`, `BattleView::fx_hang_clip_packs`.
* **Pilfer packs** (`steal_k` eid 68 = Kid's element 163, `steal_m` 143, `steal_f` 159, `steal_2` 4): one type-0x1A `main` + a type-0x19 `tech` clip pack (3 clips: SetAnim 0x80 / 0x81 / 0x82); sequences `cam0` (camera, started by the caster script at t 0), `nhit`, `spm`, `fkr0`, `fkr1`; emitters `spn1 spn2 fkro upf0-2 dwf0-2 fn00-02`; `owan` (translucent white dome round the victim, type 2 model + type 14 part) and `zuta` (the sack: a type-2 model + type-14 mesh part tossed by `fkr0` / `fkr1`). Caster (variant 0): clip 3, 0x80, React at the end of the OvalMoveS loop, 0x81, jump + landing crouch (clips 15 / 4 / 16) with the bag in the left hand. Target (variant 7) branches on the hit code: code 2 (failed steal / nothing to steal) = clip 11 (dodge), sound `thgh`, Damage (MISS pop), no sparks, no bag; code 0 (success) = `Sequence nhit`
  + Damage + `Sequence spm` + six yaw `RotateT` quarter steps (the victim spins once and ends back-turned) + `Sequence fkr0` at +8 ticks (`fkr1` follows). The bag and sparks exist only on a successful steal.
* **Approach distance**: `GetApproachPos` (7C) and the approach distance measure the **posed** attach points (attach 15 of the caster, 0x10 of the target, read from the models' current clip frame). Attach 15 is a point 1408 units in front of the root joint, so a clip that pitches the root shortens it. `BattleView::approach_distance` uses `UnitPose::attach_now`. PosMoveT is linear in the PS1 tick.
* **Joint selectors**: joint 0x22 = absolute y 0 (the floor), 0x23 = y + height/2, 1 = y + height, 0 = model y. ORIENT_BASIS selector 2 / joint 0x22 puts a splash on the floor under a lifted target (What's Up Doc?).
* Caster run-in stop points and PosMoveT paces match the PS1 within pacing differences (slow-motion pace, section 9); remaining deltas in long combo techs (173-231) are load-dependent pacing, not rule errors. Unknown: G-Force (175)'s second approach (before the jump, mid-run) still reads 1313 where the PS1 reads 745; probably the blended first frame of SetAnim 0x81.

### 5.3 ENVMAP / LUSTER / sin-x / sin-v
ASCII data in the stock hosts (`ENVMAP\0`, `sin-x\nsin-v\n`, `LUSTER`) passed to stub functions in retail. They look like debug-menu page names of the development build. Environment-mapped (reflective) shading is a **model-renderer feature** driven by the model's shading byte (`model.md`: E nybble = env mode), not by the overlay.

### 5.4 Bespoke overlays
89 overlays, 144 slots. All share the shell; 44 call `AddPrim` and at least 9 more write packets directly (0x24/0x2C/0x34/0x3C textured polys, 0x28 flat quads, 0x50 gouraud lines, GP0 0xE6 mask packets); the rest only steer models, emitters, camera and tasks (frame tasks). Resources are looked up by `(type, name)`, e.g. `(10,'kie0')`, `(0x14,'act0')`, `(0x1A,'main')`.

Families:
* **F-A mesh re-emit/deform (28)**: projected textured gouraud tris/quads (0x34/0x3C) rebuilt from model vertex lists, private ops 0x180-0x184 (start/progress/end/hide): hensin, ghost2, octdeth, 46black, saraman, ki_deth, rakugaki, theend, tumaru, mushi, garadeth, jakotu, drg_deth, fnoise, ripple (a hand rising out of the baked floor), 2boll, jitanda, miki, yamanek0 (miki's frame copy), lasbos, tekken, wipeoff, 44get, 45infe and the four summon deformers tfleaf, tgfrog, tgolem, tunico. 44get, 45infe and daimou_d share a 198-line vertex transform; 2boll and jitanda share a 4-emitter template.
* **F-B boss/monster death dissolve (11)**: screen-space 4-band gouraud strips + a mesh-dissolve renderer, resources `(10,'kie0'),(10,'kie1')`, ops 0x100/0x101/0x59: lasdes1, lasdes2, lasdes3, darkfeit, skadeth, kroto, dorured, dorublue, sfin, objcrash, bossde (lasdes2 adds camera cross-fades, song changes, a screen tint and eye-frame VRAM copies, 8.13).
* **F-C screen-band template (10)**: four 0x140-wide gouraud bands (0x28 packets, semi-transparent, 0xE6 mask) driven by a timer, op 0x100/0x101: canon ("NEGAPOSI" flash), hip, jigoku, xgiri, ghost1 (8 slots: Folding, Family Feud, Dragon Rider, robo/ryu), cook, sky, swordbox, muteki (radial glow), 155slot (sprite slices).
* **F-D gouraud line ring (4)**: 59-segment ring of 0x50 line packets with random jitter: malchera (Cat's Cradle), spark (String Phone), oomono2 (Big Catch), monfish (Hook & Sinker).
* **F-E scripted model motion/state (29)**: per-object tasks (orbit, spiral, lerp-to-point, brightness / colour fade, velocity integration, part visibility, emitter flag rewrites); mido2, uzumaki, 3mix, kuzira3 share one orbit/lerp template. Also 19helf, golem, shine, opthedo, k_monk, kamedes, daimou_d, 27earth, icerance, soidash, bboy, 3voice, enrou, hebi, shock, kamei, godhand, 25upli, 22torune, 38super, 11boru, 41grav, 43acce, 14bar, 42hevi. Largest state machines: 25upli, 22torune (jump arc with bounce), 41grav / 43acce.
* **F-F battle-scene remap (4)**: seint, unico (and tunico) override the party/enemy list getters with filtered lists; bgchng and miyademo swap backgrounds / scene trees.
* **F-G shell-only (3)**: hinsi, lasdes4, etrap (6 trap slots).

## 6. Other data
* `battle/wepon/*` (`*.bin` TIM+mesh pairs, `*.kmd`) are weapon models drawn rigidly on the hand joint; no link to effect ids. Weapon swing trails use the afterimage buffer.
* `battle/data/*`: only `pgdat.bin` (+0x10) selects effects; there is no other element -> effect table. `btbgdat` / `scenedat` select stages.
* `battle/effects/<class>/`: directory names are organisation only (slot prd counts: tech 168, monster 187, death 41, syoukan (summon) 18, black/white/yellow 15-18 each, blue/red/green 15, trap 16). The leading number in colour files (`33lez`, `41grav`) is the authoring index, not the effect id.
* Summons: slots 15/16 hold `wave0320.dat` / `st_01.mtc` / `st_03.mtc` / `st_02.mtc` / `mthun.prd` / `dummy.dat`: Saraman's sound bank and motion streams, loaded by its overlay.
* **Caught casts**: a cast caught by the other side's element trap (`docs/rules/battle.md` section 4) does not play its own pack. The action's effect id becomes 196 + c for an element (eids 197..202, overlay `etrap`) and 202 + c for a summon (record byte 0 bit 0x40, the twelve elements 37..48; eids 203..208: t53mido1, tunico, t59ufo, tfleaf, tgolem, tgfrog), c = 1..6 for the record's colour bit green, white, black, red, yellow, blue. ### 7.1 Extension block and size classes
Header bit1 -> 0xD8-byte object, bit9 -> 0xFC-byte object. Ops 36/37/43/44/49 write past 0x94 and occur only on bit1/bit9 headers; 3E writes up to 0xFC and occurs only on bit9 (113/113); op 35 on a 0x94-byte object is skipped by the engine (1397 inert uses). Object fields (byte offsets, in addition to `room_effects.md`):
```
94 u32 ext flags (op35 operand & ~3; 36/37 or in bit0/bit1)   98 ptr morph-target node (37)     9C s16 morph phase   9E s16 phase rate
A0 u8 winU  A2 u8 winV  A4 s16 winW  A6 s16 winH (36)         A8/AC s32 UV phase u,v (zeroed)   B0/B4 s32 UV rate u,v
B8/BA/BC s16 scale-rate sub-LSB (43)  BE/C0/C2 s16 accel      C4/C6/C8 s16 angle-rate sub-LSB (44)  CA/CC/CE s16 accel
D0 ptr path node (3E)  D4 u16 model motion rate (49)  D8..F7 32-byte basis matrix copy (3E)  F8 s16 ease mode (3E)  FA s16 life at 3E (L0)
```
Object flag bit 29 (0x20000000, set by op 35 or op 06) marks an extended object: each step runs the extension update and the draw callbacks take their extended path. Bits 31/30 are as in `room_effects.md`.

**Basis selector** (op 39 bytes a,b / c,d and the 4 bytes at node+0x28 of a type-0x18 entry): `a` picks a reference actor, `b` a joint. a = 0 identity; 1/9/0x19 party actor 0; 2/0xD/0x1A enemy actor 0; 10-11 party actor a-9; 0xE-0x15 enemy actor a-0xD; 3/4 average of party / enemy; 5 average of all; 8/0xC the pseudo-actor "slot -1" of the party / enemy side (the objects registered by ops 3F/40); 0x16/0x17 enemy-subset averages. Which side is the caster is inferred. `b` = joint index (0 = root); the matrix = actor yaw / pose + joint position; if `c != 0` a second joint gives a look-at (translation = midpoint, scaled by the distance). Observed values of a: 0, 1, 2.

### 7.3 Per-op semantics
* **0x35 EXT_FLAGS** (8 bytes; +2 always 0): `[0x94] = (u16@4 | u16@6 << 16) & ~3; objflags |= bit29` (only if the object is big enough). Must precede 36/37 (it clears bits 0/1) and 43/44/49 (bits 19/20/21 are always present).
* **0x36 UV_SCROLL** (14 bytes): sets ext bit 0. A GP0 E2 texture window is sent per draw: offU = byte@2, offV = byte@4, mask from width s16@6 / height s16@8 (`-w >> 3`; 0 = no window). Data: offsets 0/64/8/32 and 0/128/64, widths 0/32/64/128, heights 0/32/64/128/256 (all 0 or a power of two). UV offset = `(phase << 8) >> 16 & 0x7F` texels, `phase += rate * ticks`, rates s16 at +10 (u) / +12 (v); 256 = 1 texel per tick (|rate| up to 1536). Bytes +3/+5 are unread. Used for flowing beams, water, auras (mesh sprites only; harmless on quad sprites).
* **0x37 MORPH** (16 bytes): morph target = type-0x0E node named at +12; phase = 0, rate = s16@4; ext bit 1 is set only if the name resolved (8 of 671 do not: inert); easing mode `(u16@2 & 7)` goes to ext bits 13-15 (file values 0xFFFA / 0xFFFC reduce to 2 / 4; 5-7 act linear). Draw: `phase += rate * ticks` (s16 wrap), `blend = ease(phase)`, vertices = `lerp(mesh A, mesh B, blend / 4096)` (B = target). The ease input reflects at bit 12 (triangle wave, period 0x2000). Modes (input 0..4096): 0 linear; 1 sine-out `rsin(t>>2)`; 2 cosine-in `4096 - rcos(t>>2)`; 3 sine in-out; 4 cosine in-out `0x800 - rcos(t/2)/2`. 666 of 671 uses sit on a type-14 mesh sprite.
* **0x3D PATH_AT_SPAWN** (20 bytes; +4 cache, bytes 12-19 zero): resolve type-0x18 `name@8`; basis = the parent matrix if the emission has one, else the node's basis bytes (result written into the node). If the header duration != 0: `t = ease((frame - start) * 4096 / duration, u16@2 & 7)`, `p = Basis * curve(t) + T (s16)`, **position := p << 16** (replaces ops 08/09/27 issued earlier; later ones add). A burst emitter therefore paints the curve over its lifetime.
* **0x3E PATH_RIDE** (24 bytes; bytes 12-23 zero; needs bit 9 and an op 0F before it): stores node (D0), ease mode s16@2 (F8; -4/-6/-8 in 13 uses fall to linear), L0 = lifetime (FA), copies the basis (D8) and puts the object at `curve(0)`. Each tick (skipped while life == L0): `t = ease((L0 - life) * 4096 / L0)`, target = `Basis * curve(t) + T`, **velocity := (target - pos) / ticks** so the integrator lands on it; acceleration is irrelevant. If node+0x20 bit 0 is set the basis is rebuilt from the live actor every tick (the path follows a moving joint). 110 battle uses.
* **Type 0x18 path node** (59 entries): +0x00 rot 3x3 s16, +0x14/18/1C s32 T (both overwritten at runtime from the basis bytes; the file holds identity), +0x20 u32 flags (bit 0 = live basis), +0x28 u8 a,b,c,d (basis selector), +0x2C pointer (set at load to `payload + 0x34 + 8*N`), +0x30 u32 N, +0x34 N x 8-byte head records (purpose unknown; in `dai_h` they equal the end keys), then the curve block: u32 M, 16 unread bytes, M keys at +0x14: `s16 x,y,z; u16 t` (t ascending in 0..0x1000). Sampler: linear between the bracketing keys (extrapolates before the first), clamps at the last, M <= 1 returns key 0. Referenced curves have 2-608 keys.
* **0x3F / 0x40 SLOT_A / SLOT_B** (4 bytes): need op 05 earlier. Register the sprite's type-0x14 model (else the particle itself, flag 0x80) as the battle overlay's pseudo-actor slot A / B; battle scripts address them as actor index -1 / -2 and basis selectors 8 / 0xC use them. Obj flag bit 31 (set only for a particle bound itself) clears the slot when the particle is freed; a bound model outlives its particle and keeps the slot where the particle last placed it. Selector 8 / 0xC frames a bound model by its own yaw (the particle's y angle), a bound particle by `-atan2(vel z, vel x)` (tfleaf's cameras `1` and `2` frame the wolf model's last place and yaw after its particle is gone). Pure binding: no motion change.
* **0x48** (12 bytes): would install a draw callback from the u32 at +4 only if non-zero; it is 0 in all 48 uses, so it is a **no-op**.
* **Sprite type 20 (0x14) = type-0x0B model object**: op 05 `type=20` names a type-0x0B drp record = an Mdl container (`model.md`; S5/S6 may be absent). Each tick, if obj flag bit 29 (ext block, set by op 35), the model takes the object's draw colour, position (pos >> 4), angles and scale; with ext bit 21 it advances its motion by `ticks * motion-rate / 256` keyframes (face-velocity flags 13/14 build the facing matrix first), poses and draws into the ordering table. Implemented for the title (`title_scene.md`). Texture binding: the record *name* decodes as hex: chars 0-1 = CLUT row, char 2 nibble (bit 0 = tpage y 256, bit 3 = CLUT x 256), char 3 = tpage x / 64.
* **0x49 MODEL_BODY** (10 bytes): requires sprite type 0x14 from op 05 (141/141). Binds to a live instance of the type-0x14 resource; if clone (+5) the model is duplicated per particle (obj flags 0xC0000000, freed with the particle). +2 show: model+0x22 := 0/1; +3: model flag 0x200 set / clear; +4: model flag 0x100 set / clear (hide bits); the motion index is selected from the op-04 byte and `n = s16@8 & 0x1FFF` (0 -> 1; 0 in 113 uses); u16@6 = motion advance per tick in 1/256 frame (64 in 117/141 = 1/4 frame per tick); ext bit 21 required. The particle's pos >> 4, angles and scale are copied into the model each tick, with an optional velocity-facing matrix (obj flags 13/14).
* Ops 34/38/39/3A/3B/41-46, blend 5-7, flags 12/24/28/29 and sequence ops 28/29/2E/65 are specified in `room_effects.md` (28/29 are controller rumble, 2E/2A screen shake, 65 ambient-colour fade).

### 7.4 Is a generic emitter player fully specified?

### 8.1 Module layout, pacing and host side
Code: `src/game/effects/bespoke/` (`overlay_base.h` plus one file per port family below; `emitter_patch.cpp` (Ice Lance, Earthquake), `summon_ports.cpp`, `kamei_port.cpp`, `line_ring.cpp`, `scene_remap.cpp`, `mesh_water.cpp` (ripple); `band_wipe.cpp` (the six screen negatives), `actor_script.cpp` (the ActorScript base and 3voice) and `mesh_warp.cpp` (14bar's body wobble, wrapped by its ground part)). Registration: `BespokeRegistry` (`bespoke.cpp`); every overlay name has one module, except that a ground part (`add_ground_part`) wraps the module registered before it under the same name. `BespokeInfo::battle = false` keeps a module out of battle. Trace: `OC_BESPOKE_TRACE=1` logs every 10 ticks the steered models (position, rotation, scale, colour, flags, copies) and the module's tasks.

**Gouraud shading is per vertex everywhere.** The PS1 GPU interpolates the vertex colours of every G3 / G4 / GT3 / GT4 packet (and of the type-15 'line', a LineG2 from the object colour to black), so a gradient mesh (the field `enc1` ring, black -> blue; the bespoke glow discs, rings, flashes) must reach the batch with one colour per corner. `FlatQuad::c[4][3]` (bespoke untextured prims) and `DrawQuad::r1 g1 b1` (line far end) carry the corner colours; consumers use `ParticleBatch::quad`'s per-corner overload. Flattening to one colour per triangle breaks gradients into wedges.

**OpenCross: ring smoothing (enhancement).** At high resolution the PS1's 16 / 32-sided rings show facets. `effects/strip_smooth.*` finds closed quad strips in an untextured mesh (every quad shares two opposite "rung" edges with its neighbours and the chain closes; a quad may share a third edge, the common rail of a multi-band ring: the field `enc1` is two bands over radii 1342 / 2104 / 2348, 16 segments) and splits each quad into N sub-quads along the loop (N = longest rail segment in screen pixels / 6, clamped 1..8, one N for all rings of a mesh) on a Catmull-Rom curve through the original rail vertices (radius and extent unchanged; colours lerp). Anything not a closed strip is untouched; a ring whose rail is shared with a non-refined primitive (the `enc0` disc's fan) stays as is, with every ring sharing a rail with it. Triangle-list meshes are handled the same way after consecutive triangle pairs are merged into quads (`smooth_triangle_rings`). Applied in `FieldWorld::draw_effects` (mesh sprites, object space before projection) and to the bespoke `FxFrame::flats` quads in `BattleView::fx_draw` (screen space). Toggle: `[Enhancements] SmoothEffectRings` (default on, Esc > Enhancements), independent of `Ps1ResGraphics`.

**Overlay pacing (dt).** The PS1 main loop runs the frame code once per iteration, where `dt` = vsyncs since the last frame (clamped 0..10; the frame-rate lock and the slow factor change it). Sequence tasks (`elapsed += dt`, wait `-= dt`, the overshoot carried into the next wait, so a short-wait loop catches up inside the iteration), emitters (dt sub-steps; period and duration count per sub-step) and objects (`life -= dt`, motion scaled by dt) are dt-invariant. A bespoke overlay's tick is also called once per iteration and reads dt where it integrates (25upli: `pos += vel * dt >> 12`, `vel += dt * 0x3000`), but anything it does per call happens once per iteration (25upli case 6 fires `kem0` on every call once a piece is below ground). dt is the real loop cost of the PS1, 1..4 (Uplift 19 runs dt 3 for the cast and 2 for the pit phase). RDE on a PC finishes a frame in one vsync, so its dt is 1 and an overlay fires per 60 Hz frame (the OpenCross default). OpenCross model: `EmitterSystem::begin_overlay_tick(new_window)` / `end_overlay_tick` around `BespokeEffect::tick` (`BattleFxRun::tick`). With a pace of dt ticks (`BattleFxRun::set_pace`, env `OC_FX_DT` = "N" or "t:N,t:N" by pack tick) each overlay fire site (emitter name + ordinal within the tick, `fire` / `fire_at`) fires at most once per window of dt ticks; a one-shot site fires at its first call; motion stays per tick. Not modelled: the odd-only life grid and 2-tick spawn groups of the stock emitters (sampling parity only), a per-call `rand` (the shake of case 1) draws once per tick. Totals of the paced Uplift `kem0` objects match the PS1 (2272 vs 2478 summed); Gravitonne, Volcano and Inferno match in total without pacing.

**Lists and units seen by overlays.** Overlays walk three lists: the acting (caster) list, the target list and everybody; each ends with NULL. An entry is a 0x30-byte unit control block (model pointer, home x / y / z as s16, group, flags with bit 0 = death, bit 0x8000 = monster); overlays always go through the entry's model. Model fields (PS1 axes, y down): colour (0x80 = 1.0); flags (bit 0 = not drawn by the stock pass, 1 = semi-transparent, 0x200 = drop shadow); position 20.12; rotation (4096 = turn); scale (0x1000 = 1.0). Overlay-callable model operations: set / clear flag bits, SetAnim (clip, blend ticks = flags & 0x1FFF) and run an anmseq script (idx >= 0x80 = entry idx - 0x80 of the assigned external table; overlays assign the pack's last type-0x1A entry named `dead`).

**Host** (`effects::FxModels`, filled by `BattleFxRun::init_models` when a bespoke module starts): one `FxModel` per battle unit (home = stand position, `rot` = the model block's angles, `rot[1]` the unit's 12-bit yaw: 0xC00 looks along +x, 0x400 along -x; while a model is steered the effect selectors and the camera anchors read its position and its yaw from here, not from the view; a model no overlay steers carries the unit's live position every tick, `BattleFxRun::sync_unsteered`, so an overlay reading a target its reaction script has tossed sees the lifted y, as the PS1 model block does), the caster and target lists, and the per-target loop cursor at the time a private op arrives. A module writes the fields; `BattleView` draws a steered model (`steer`) at `translate(pos) * home yaw * y-flip * Ry(-home ry) * RotMatrix(rot) * Scale` (`fx_model_pose`, interpolated between ticks), multiplies its tint by the colour, skips it when `hidden`, holds its pose while `anim_speed` is 0 and plays its clip at any other speed word the overlay set (0x40 = normal), drops its shadow when flag 0x200 is clear, and consumes SetAnim / anmseq requests after the tick (`BattleView::fx_model_requests`; the pack keeps every type-0x1A table by tag, `FxPack::tables`). When the effect ends the models return to the view's own placement.

**Model copies** (`FxModel::copies`): overlays that re-skin a model and draw it themselves copy the posed vertex buffer, transform each skinned world vertex, and draw the result. The host skins the posed mesh on the CPU with the mesh pipeline's palette, moves every vertex to the PS1 world, adds the copy's offset, calls the module's per-vertex function, projects with the effect view, culls back faces and sends each face as one textured triangle at the OT slot of its mean depth >> 4 with the copy's colour (0x80 neutral) and blend (PS1 ABR 0..3 -> particle blend 1..4, -1 = opaque) through the effect painter's sort (`BattleView::fx_model_copies`). Deviation: a semi-transparent copy blends every texel (the PS1 blends only STP texels); the lit path (flags 0x160) is not reproduced.

**Emitter hooks** (`EmitterSystem`): `patch_op(header, op, v)` rewrites a record (ops 08 POS, 0A VEL, 19 ANGLE, 39 ORIENT_BASIS selector bytes) or POS via `set_position`; `set_object_hook(name, fn, after)` replaces a per-object callback (runs before the object's step) or draw callback (after the step); `for_each_object` iterates live objects; `set_draw_suppressed` = the overlay draws the mesh objects itself; `fire(name)` = one firing at the record's own position. `own_header()` limits loops to the pack's own emitters (not the particle library).

`ps1_square_root0` reproduces the PS1 libgte `SquareRoot0` bit for bit (leading-zero count, then the exe's table, read from `prog/slps_023.64` at run time), so a negative argument reads what precedes the table as on the PS1 (mido2's radius). Private-op operands: the host hands the s16 words from record +4 on; `OverlayFx::arg(a, n, off)` reads the word at record offset `off`.

### 8.5 Ground ports: the stage ground and shared bake (`ground_ports.cpp`, `_b`, `_c`; base in `ground_base.h`)
**The ground**: the stage's type-0x12 `ring` mesh (sprite type 19; a zero mesh name takes the stage's one ground, and the object's extended-object bits never reach it, `battle_stage.md`) becomes a ground object with a vertex array, an FT3 list, a 10 x 10 grid of 0x1C-byte cell records (index `cx + 10 row`, cell left x = `-0x1400 + 0x400 cx`, top z = `0x1400 - 0x400 row`: uv0 +0, clut +2, uv1 +4, tpage +6, uv2 +8, uv3 +0xA, corner colours +0xC / +0x10 / +0x14 / +0x18 for left-top, right-top, left-bottom, right-bottom), flags (bit 0 = the stock draw skips the ground, bit 1 semi), a colour, and a GT3 list. The ground draw takes a rect and skips a cell iff `x >= r[0] && x < r[2] && z > r[3] && z <= r[1]` (x / z = left / top edge); it has an OT bias. **Host side** (`effects::FxGround`, `fx_ground()`; `game::StageScene` registers its own): `cells`, `rim` (the FT3 then GT3 triangles), `rgb` (the ground colour), `ring_colour` (the `ring` emitter's op-0x20 record >> 4); per overlay `skip_stock` (flag bit 0), `bias`, and, rebuilt every tick by the overlay, `draws` (its ground rects: one draw shows every cell any rect keeps) and `prims` (`FxGroundPrim`: baked pack-mesh packets in PS1 world or camera space, drawn by `StagePipeline::draw_prims` with the stage atlases found by tpage mode + CLUT, corner colour x mesh colour / 128, blend = mesh semi + ABR or the packet's own, slot = average z >> 4 + mesh bias, back faces culled unless the overlay's drawer is two-sided, `depth_cue` = per-corner fog for the overlays' private fog builders); `warp` + `warp_emitters` + `draw_bias_add` (46black / 14bar per-vertex hooks, 8.6). The overlay's destructor gives the stock ground back; `BattleView::fx_end` resets the bias to 100.

**The shared bake** (wipeoff, jitanda, 2boll, saraman, 11boru, 25upli, 42hevi, tekken; `bake()` in `ground_base.h`): per FT3 / FT4 / GT3 / GT4 packet, `X' = s16(x + 0x1400 + offX)`, `Z' = s16(z - 0x1400 + offZ)` per corner; the cell comes from the sums (triangles / 0xC00 truncated, quads `(sum + 0xFFF if negative) >> 12`), record `cx - 10 cz` (no clamp); per corner `u = (X' - 0x400 cx) * 4`, `v = (0x400 cz - Z') * 4`; uv and colour = `lerp(lerp(c00, c01, v), lerp(c10, c11, v), u)` with `lerp(a, b, t) = a + ((b - a) t >> 12)`; the colour is written in mode 1 always, in mode 2 only while the packet colour is exactly 0x808080 (flat packets share one slot: the first corner sticks in mode 2, the last in mode 1); then clut := cell +2, tpage := cell +6. Corner order = the builders' (textured triangles idx1, idx2, idx0). Meshes are drawn with `v' = View(RotMatrix(r) (v - c)
+ c + q)`, c = the truncating mean of the vertex array. Pack meshes are parsed packet by packet from the raw drp (`FxContext::pack_prd`). Baked meshes the pack's emitters draw (tekken h00n, 11boru hahe / hm**, 25upli hah3, 42hevi suri via `yuka`) are drawn by the port with the objects' own transform / colour / blend / bias, and the host's draw of those emitters is suppressed (`EmitterSystem::collect_meshes(..., with_suppressed)`).

### 8.8 The overlays' private model draw (`model_draw.h`, `model_deform.cpp`, `mesh_tech.h`)
Most re-skinning overlays carry their own copy of the stock model draw. One CPU helper reproduces it.
* **Host** (`BattleView::fx_skin_unit` / `fx_skin_pack`, `FxModels::skin` / `skin_pack` / `attach`): skins the posed model as drawn (steered placement included) to **world vertices** (PS1 axes) with per-vertex normal bytes `clamp(R x (VDDM s8 << 5) >> 12, +-0xFFF) >> 5`, R = the world rotation of the joint the record belongs to; an 8-byte vertex uses its own VDDM record and joint, a 16-byte vertex the record of rec0 with J2 (the field / title variant clamps +-0x1FF and shifts >> 2). The importer keeps the VDDM bytes (`SkinVertex::normal`, `normal_joint`; `model.md`). Attach points: `fx_attach_unit`.
* **Part colour word** CW: per channel `(part rgb x model rgb) >> 7` truncated to a byte; byte 3 = `(F & 0xF2) | 4` (jakotu fnoise rakugaki ki_deth drg_deth octdeth) or F as is (hensin ghost2 and the stock draw), OR'ed with model flag bits 0x2 (semi), 0x100 (part skipped), 0x20 / 0x40 / 0x80; tpage ABR = `(F >> 2) & 3` unless the model's own tpage is used as is (model flag 1 with bound texture: `force_abr`).
* **Per face**: triangles are drawn when NCLIP > 0, quads when NCLIP(v0,v1,v2) > 0 or NCLIP(v1,v2,v3) < 0 (the F-B dissolves: <= 0); OT index = average SZ (quads: of v1 v2 v3 after the fourth projection, fnoise's frost draw included; only its shards take the mean of four), part flag 0x10: min SZ (hensin ghost2 octdeth GT3: max SZ) >> 2, then >> the OT shift (OpenCross: z >> 4); quads past OT 0x1000 are dropped. Packet P1 = the module's corner colours (else CW) with the face UVs; byte 3 & 0x60: UVs from the normals (jakotu fnoise: `n ^ 0x80`; hensin ghost2: `(n >> 1) + 0x40`, `(n >> 1) - 0x40`; rakugaki: planar) and, unless bit 0x80, the env page `((byte 3 & 0xC) << 3) | page` with the module's CLUT; with 0x40 P1 is forced semi-transparent and P2 (CW, the face UVs and texture) goes into the same OT entry after it, so the textured model draws first and P1 on top.
* **Plane clip** (hensin, ghost2, octdeth): a polygon wholly at y <= P is side 0, wholly at y > P side 1 (drawn unless skip[side]); a cut one is walked v0 v1 v2 (quads v0 v1 v3 v2) into two lists: push the corner, on a crossing push the intersection `t = ((P - a.y) << 12) / (b.y - a.y)` (interpolating position, normal bytes and UV), switch lists and push it again; a list is side 1 when its first three corners have y >= P - 2; 3 corners = GT3, 4 = GT4 (0, 1, 3, 2), 5 = GT3 (0, 1, 2) + GT4 (0, 2, 4, 3). The hensin cutter variant reports the first two intersections of every cut polygon.
* **White CLUT passes** (the "ghost" / dissolve look): a pass drawn with ABR 2 (B - F) through a white CLUT runs first in each OT entry (after the normal ABR 1 pass in submission order) and blacks the silhouette out before the texture is added. White rows: the battle's global rows 243 (index 0 transparent) / 245 (all 256 white) for opthedo and kamedes; the model's own row with non-zero entries -> 0xFFFF for mushi ki_deth daimou_d; garadeth's all-0xFFFF rows; the F-B dissolves' copy (non-zero | 0x7FFF). `FxPrim::white` 1 / 2 = the host's white copies of the model texture.
* **Host additions**: `FxPrim::TexSrc` Model / Vram (a 256 x 256 window of the pack VRAM `FxPack::build_vram` with the overlay's tpage / CLUT, after `FxModels::vram_moves`: MoveImage / DR_MOVE / cyclic scroll) / PackModel (the pack's sprite-type-20 model) / Capture (the frame copy `FxModels::capture` asks for, u / w in layer pixels of the 320 x 224 picture; the host makes the copy before the first item filed at or above the request's slot, at any render scale and aspect, and maps the pixels through the letterbox; ripple's warp grid); per-corner colours for every textured primitive; `FxModel::own_shadow`; `anim_speed` 0 (the host skips the pose step); `grey` (a CLUT row fade re-uploads the model textures); `BespokeEffect::stock_op` (the overlay's dispatcher sees stock ops first: the F-B 0x59 override); `EmitterSystem::fire_at` (fire + the object's position := centroid << 16; optional tag = the overlay draws the object, `collect_tagged`); `FxModels::caster_override / target_override` (8.10); `FxModels::pad_edge`; `FxModels::PackDrive` (the overlay-driven pack model: place, SetAnim, streamed motion files hung on it as its external clip table, anim speed; `UnitPose::play_clip`, `import::load_mdl_clips`); `FxModels::suppress_main` (the overlay starts `main` itself); `fx_pack_model_binding` (a type-0x0B model whose name carries no texture code; saraman).

Not modelled: the weapon trails / lights / parts ops (not used by the three scripts).

### 8.17 Dopplegang: the creature pool and the unit swap (`Battle::dopple_*`, `Battle::transform`, `BattleView::open_dopple / apply_form`; hensin 0x182 / 0x183)
* **The pool** is a 256-bit mask in the save: 16 x u16 = save block head `0x568..0x587` (`0x188 + 0x3E0`) = field global variables `0x3E0..0x3FE` = the battle script variables `0x60..0x7F`. Battle start copies it in, battle exit copies it back. A new game does not clear it; playinit ORs the NG+ table into it. Bit `n` of word `w` = pool slot `w * 16 + n` = the monster.bin record whose `+0x2B` holds that number (variants of one creature share a slot: records 25 / 62 / 105 all say 10; `+0xA6` bit 7 = not doppelgangable, e.g. records 0, 5, 6, 7, 46, 219).
* **Who enters it**: the kill script's first op (`65 A6 00`, run for every dead enemy) adds the enemy's slot when the PC of the last confirmed command is character 26 (Sprigg) or wears item `0xFC` (Forget-me-not Pot) in any of its three accessory slots, and the enemy's `+0xA6` bit 7 is clear. The kill script runs whoever killed the enemy, so any death during that PC's last command counts.
* **Slot table** (`src/battle/dopple_table.h`, 220 valid records of `{u16 model, s16 val}`): slot -> battle model number (`kBattleModels` index, file group 0xE entries `3m + 2 .. 4`; equals monster.bin `+0x2D` of the slot's own record except slots 46 and 219); `val` is only tested non-zero by the debug list.
* **The pick**: confirming a grid cell whose element is `0xEE` (238) opens a window listing entry 0 = the caster's own character and then one entry per set pool bit, ascending, named by sysmes table 0x19 (monster names); two columns, six rows visible, scrolls by row. Confirming entry 0 while the unit wears its own form is refused (SFX 0x18); cancel returns to the element list. A confirm stores the model (| 0x8000 for a PC) and the FORM (the character id for entry 0, `slot + 0x40` for a creature); the cast is element 238 on the caster (pgdat 238 `+4 = 0x44`, mode 1, power 0: the rules do nothing) with the hensin overlay (eid 11) as its effect. Layout: entries at `x = 0x40 + (s & 1) * 0x66`, `y = 0x38 + (s >> 1) * 16`, style 0xB8, the first entry green 0x008000, the rest 0x808080, no selection highlight, cursor at (`0x36 + col * 0x68`, `0x3A + row * 16`), banner from the header float, window skin drawn 8 px outside the interior rect; while the list is open the target info window shows the caster. The scroll clamp comes from the byte creature count, so only a forged all-256-bit pool wraps to 0 and cannot scroll. A PS1 capture with a forged Sprigg save (pool slots 1, 3, 10, 18, 26, 53, 54, 61, 71, 141, 220-224) confirms the layout: 16-line row pitch, both columns and the cursor where the formula puts them, the same 12 entries on the first page, and 14 Downs end at top row 2 with the cursor on an empty row 5 (the named-count gate). Pool slots 220 and up are listed (the capture shows one more name and four blank entries for 220-224) but lie past the 220-row creature table; no monster record credits a slot above 217 (the highest `+0x2B` of a record without `+0xA6` bit 0x80), so they exist only in forged saves, and OpenCross refuses such a pick instead of reading past the table.
* **The swap** (hensin ops 0x182 / 0x183): the transform state is set (1 for a Dopplegang pick, 2 for Pip's form change, which runs through the same swap and clears the battle-exit restore flag, `docs/rules/battle.md` 9.2); the unit's HP, max HP (from a character form) and the `0x80` flag are saved, and from a character form only the whole 0x410 record is backed up (by a Dopplegang pick; Pip's form change backs nothing up but becomes the unit the saved max HP and the battle-exit restore belong to). The unit's 0x410 bytes are then cleared (inflicted statuses, timers, modifiers gone), the gauge set to -1, monster.bin record `form - 0x40` (0xB0 bytes: stats, innate colour, gear ids, status words `+0xA8 / +0xAC`, level masks, the 48 element cells) copied over it (for the way back: the whole backup, its stamina, AP and used cells included; every swap start sets the battle-exit restore flag, so the way back always finds it set and clears it; the character's party record, 0xCC bytes, would be taken only with that flag held clear, which only the debug program does), and HP / max HP restored: the HP is the swapped unit's of now, the max HP and the `0x80` bit those saved at the last swap that started from a character body, whichever unit that was (after Pip's form change, Pip's max HP; the `0x80` bit is the KO bit and always clear there, as only a standing unit changes form). The five gear records are copied; status word `+0xA8 |= 0x400400`; the new model binds with texture load (TIM `m * 3 + 2` to (0x280 + 0x40 u, 0), CLUT row `0xF0 + 2 u`), counter := 8, AP := 8, control bit 12 (eyes) set for a character and cleared for a creature; the creature's name is written, the cell flag bits stripped (`& 0x3FFF`) and the element menu rebuilt from the record's cells. The unit casts the CREATURE's techs, and the creature's own record usually holds a `0xEE` cell (130 of the 222 records), so the way back (entry 0) and the next form are one pick away. A PC unit stays a PC (slot, party, results); only record, grid, name and model change.
* **Enemy-side 238 never happens in retail**: the Big Catch handler is not a Dopplegang swap; an enemy could only reach 238 through the battle-script element picker, which accepts a grid cell only when its element id is `< 0x7E`, pgdat byte 0x14 == 0xFF, byte 0 & 0x44 == 0 and byte 4 & 0x41 == 0 (ported as `pick_element` in `src/battle/pac_opcodes.inc`, a no-op on every shipped grid; no enemy script names 238). The global debug flag (pad bit 0x10 in a dev-build gate) would list every table row with non-zero `val` and clear the cell's cost bit; not reachable in the retail UI (dev knob `OC_DOPPLE_SLOTS=debug`).
* **OpenCross port**: `Battle::transform(unit, form)` (form >= 0: monster record; < 0: the way back): `Unit::form`, the character's record kept in `form_backup_`, the last character-body max HP in `form_max_hp_` (set by a form change from the own form and by `Battle::evolve`); HP stays, max HP = `form_max_hp_`, statuses / timers drop, the Unit takes the record's stats / innate / gear / status words / cells (`usable` by id like an enemy), AP 8, countdown 8, gauge -1; the way back puts `form_backup_` back (its stamina too) with the HP of now, max HP `form_max_hp_` and countdown 8, and writes that max HP into the record (`PartyMember::stat[0]`); `form_body_unit_` is the slot of the last character-body form change; at the end of the fight `Battle::exit_unit` gives back the character's unit (`docs/rules/battle.md` 9.2); writes to the party record (`PartyMember::cells / qty`, trap losses) are skipped while a creature. View: `Ui::Dopple` (the list), `pending_form_` set at the pick, `apply_form` at hensin 0x181 (or at the action's end when a cut-short effect never got there): `bind_unit_model` re-binds model / scripts / sound group / weapon, the idle clip restarts, eyes off; `unit_model_stem`, `ctx.monster / model_num` and the blink hooks read `Unit::form`. Pool: `BattleOptions::dopple_mask` in, `Battle::dopple_mask()` out (`FieldWorld::dopple_mask / set_dopple_mask`), script vars `0x60..0x7F` seeded at battle start. Dev: `OC_DOPPLE_SLOTS=1,2,9|all` (`all` sets all 256 bits), `OC_DEV_FORM=<slot>` with `--cast 238`, `ocbattleview --ui 8 --party 26`.

## 9. Generic player: rules
Code: `src/game/effects/emitter_*.cpp` (+ `emitter_system.h`, `emitter_internal.h`), `sequence_player.*`, `src/game/battle/battle_fx.*`, `battle_view_fx*.cpp`. Audit tool: `ocbattle fx-audit`.
* **Resident data**: sheets / meshes / TIMs of `battle.prd`. The mesh importer's input is the resident VRAM written as egfx sections followed by the pack's own (`read_ctd` / `write_ctd` in `battle_fx.cpp`; a malformed pack section ends its list instead of dropping the meshes: eid 3 `yamanek0.ctd`). Resident emitters are registered stopped (`EffectBank::add_library`).
* **Who starts a pack's sequences**: the stock hosts start only `own` / `main`. Every other sequence is started by the actors' anmseq scripts, ops 0x68 / 0x7D (the pack's group first, else the global registry = the camera timelines of `tana`). 0x68 skips a repeat of the last tag. Op 0x50 (camera select) keeps a tag memory too, but both memories are cleared by the return hop that ends every weapon attack, the enemies' included, so in the shipped battles 0x50 always selects. OpenCross: `BattleFxRun::start_sequence` from `BattleView::on_script_event`. A pack without `main` stays alive while the caster's script runs. A root sequence that neither `main` (op 0x2F) nor any script names never runs: the trap-summon packs carry the sequences of the creature's own summon pack unreferenced (tunico holds unico's `any`, `heal` and `horn`, which unico's `main` starts with op 0x2F; tunico's `main` starts only `kira`, `aper` and `test`), and with them the meshes those draw (`niw0`, `niw1`, `niji`), whose CLUT rows (256, 231) / (256, 233) and page x 768 the trap pack's egfx does not upload.
* **Waits are signed**: each command adds its s16 wait; a negative sum means "overdue" and the next commands run in the same frame (`MARK` waits of -1 would otherwise make 2 packs run 65535 ticks).
* **Per-target loops**: a task has a target cursor and an inherited target. Header flag bit 0 = the sequence loops over the targets: op 0x4D (and the end, op 0x21) moves to the next target while one exists and restarts at the loop label (+0xC); op 0x4E sets the label and resets the cursor. Op 0x22 with a target k != 0 starts a **clone** of the emitter whose op-39 selectors 1 / 2 (bytes a and c) are rewritten to 9 / 0xD + k, so it keeps following that target. Op 0x2F with k != 0 starts a copy of the child whose target operands are rewritten: 0x45 s16@10 := 0, 0x46 / 0x57 / 0x59 s16@10 := k, 0x47 / 0x6F / 0x70 s16@8 := k, 0x58 byte@0xB := k, and its 0x22 emitters cloned. **Op 0x4D with another target left returns at once with the wait cleared**: the op's wait (Magma Bomb 87) is paid by the last target's pass only.
* **Actor selectors**: the lists are the action's casters, targets and everyone (not the two sides): 1 / 9 caster 0, 2 / 0xD target 0, 0xE..0x15 target 1..8, 10 / 11 caster 1 / 2, 3 / 4 casters' / targets' centroid, 5 everyone, 0x16 / 0x17 targets' centroid on the ground, 0x19 / 0x1A the *side* point (-2048, 0, 0) facing 0x800 when caster 0's / target 0's x < 1, else (2048, 0, 0) facing 0. Rotation = `RotMatrix(0, actor yaw, 0)` (mean yaw for centroids). Joint b: 0 origin, 1 origin + height offset, 0x22 origin on the ground, 0x23 half the height offset, other = attach point `b - 2` (S3 table). OpenCross: `FxUnit::attach` = `UnitPose::attach_now` x the unit's model scale words (scaled models: Fire Dragon 453's fireball inside the 0.28-scale form 2). Look-at basis (c != 0): `RotMatrix(0, -ratan2(dz, dx), ratan2(dy, |dxz|))` then `ScaleMatrix(|dxz| * 8192 / rcos(pitch), 0x1000, same)` = X / Z columns x distance / 2048.
* **Model copies**: ops 0x6F / 0x70 (target s16@8), 0x71 / 0x72 (all targets), 0x77 / 0x78 (caster s16@8) take / free a copy of the model block and joints; joint lookups read the copy, so effects stay on the pose of that moment while the model moves. A pack start frees all copies. Nothing extra is drawn.
* **Visibility**: model flag bit 0x1 is the hide bit: 0x30 / 0x31 everyone show / hide, **0x32 / 0x33 show / hide the caster's side, 0x34 / 0x35 the other side** (actor flag 0x8000 compared with caster 0's), 0x5B / 0x5C targets, 0x5D / 0x5E casters. **Bit 0x100 is not a hide bit**: it selects the GTE-lit packer (flags & 0x160, `model.md`): 0x61 / 0x62 targets lit on / off, 0x63 / 0x64 casters, 0x68 / 0x69 everyone. Bit 0x200 = drop shadow: 0x74 clears it on the targets, 0x75 sets it.
* **Screen colour layers**: ops 0x2B / 0x2C are not fades: they ramp the colour of full-screen POLY_F4 layer 0 / 1 ((0,0)-(0x160,0x110), effect-OT slot 5 / 6, drawn while not black) from its current colour to bytes @+9..+11 over s16 @+4 ticks; mode byte @+8 (0xFF = keep): 0 opaque, 1..4 = ABR mode - 1 (2 = additive flash, 3 = subtractive dim). Only the pack-start reset clears them (the packs ramp back themselves).
* **Depth cue**: op 0x24 = fog flag on and every actor on the depth-cued renderer; op 0x6C off; ops 0x49 / 0x4A / 0x4B put everyone / the targets / the casters back on the plain renderer. Off by default (battle init, effect start). Op 0x2D ramps show only while it is on; effect objects with flag bit 17 get `DpqColor` (sprites, built-ins) or the per-packet cue (meshes). Op 0x25 has no case (no-op). A pack may leave the depth-cue flag on (ramps end at near / far 0 / 0, colour 80; Magma Bomb) until the command-orbit branch or the next effect start clears it; the end hook resets only the units (shadow bit, model copy, idle). Screen colours, warp and lens flare are restored by the pack / `fx_end`; stage layers by the pack's own on ops. `OC_FXDBG=1` logs the state at pack start / end / group end / command input.
* **Screen copy warp** (ops 0x3E / 0x3F / 0x40): 0x3E turns the warp bracket on and resets colour 0x808080, angles, translation, offset, ABR; 0x3F off; 0x40 ramps over s16 @+4 ticks to angles s16 @+8..+0xC, translation @+0xE..+0x12, offset @+0x14 / +0x16, colour bytes @+0x18..+0x1A; ABR = byte @+0x1B at once. While on, the previous game frame's picture is drawn again over the new one at effect-OT entry 1 once per game frame, in 80-pixel strips: the rate follows the game frame, not a clock. RDE's game frame is one vsync, so the pass runs at 60 Hz (a game frame a pack's slow motion stretches is one pass), and the additive feed-back of element 271 whites out about 36 vsyncs after the warp starts; a heavy pack's PS1 game frame takes 2-3.6 vsyncs, so the PS1 picture climbs more slowly. OpenCross follows RDE: one feed-back pass per game tick, the scene under the strips stays live. Vertex `(x - 160, y -
  112) * 4`, z 0, rotated, translated (+0x1000 in z), H = 0x400, centre (160, 112) + offset, 16-bit texture of the draw buffer, colour-modulated, semi-transparent with that ABR. Data: ABR 0 in 83 ramps, 1 in 15; most zoom (translation z -48..-348) = a zoom-blur double image. **Black texels are drawn, not skipped**: a companion step at effect-OT entry 0 sets the mask bit, self-copies the frame in 0x40-px FT4 strips, and clears it, so every pixel of the next frame's copy source carries STP = 1 and a texel 0x8000 blends. RDE drops that step: its strips sample the colour target itself, which holds no STP bits. OpenCross blends every texel (the same picture). OpenCross: the 3D scene goes into a render target, is copied back, then the strips (`BattleView::fx_warp_*`). The stage timelines' ops 0x3E-0x40 ("frame afterimage", `battle_stage.md`) are the same cases and the same state; `BattleCamera` routes them (warp hook) into `BattleView::fx_warp_op`. Lifetime: the effect end hook does not clear the warp; it ends at the next effect start, battle-script op C1, and while no shot / timeline runs. OpenCross clears it at `fx_end` (no timeline running) and when idle so a spell never leaves the double image on later attacks.
* **Slow motion**: op 0x79 (and 0x56 with s16 @+10 != 0) sets a frame-lock factor m = byte @+8: one game tick per m video frames when m >= 2; op 0x56 with s16 @+10 == 0 sets a slow factor k. A pack/battle reset clears both. With k: e = vsyncs since the last frame (1..10); `d = e - k`; d < 1 -> ticks T = 1 and a `1 - d` owed-frame count, else T = d + 1 and 0; the frame ends with a VSync of n (n >= 2) vsyncs since the last call. With m >= 2 the frame is padded to a multiple of m vsyncs (`n = 1, limit = m; while (e - limit > 0) limit = m * ++n`, T = n). At one vsync per video frame (OpenCross) k gives: k = 1 changes nothing; k >= 2 alternates a frame that pays k vsyncs with one that measures them: **2 game ticks per k + 1 video frames** (k = 2: 2 / 3, k = 3: 1 / 2) (`BattleView::fx_slow_skip`). Measured PS1 m path (chgtar = element 337): m = 2 gives a game frame every vsync (no slowdown), m = 4 every 2 vsyncs, m = 8 every 3-4 (3 / 4 alternating for 8 frames, then 3), shorter than the arithmetic suggests. Why: the wait of n vsyncs that ends the frame is counted from the previous wait, but gives up after a busy-poll time-out of (n - 1) fixed poll batches, about 10 ms per extra vsync on the PS1 CPU, so a long pad (m = 8) returns after 3-4 vsyncs. The time-out is a CPU-speed artefact of the PS1, not a pacing rule; so is the k path's slower PS1 rate at k 2-4 (a heavy pack's loop iteration costs 2 vsyncs; "Slow-motion pacing is load dependent" below). **Rule (OpenCross)**: one video frame = one vsync, no time-out: one game tick per m frames on the m path, 2 / (k + 1) on the k path; this is what the formula gives on RDE's one-vsync loop, so the PS1's load-dependent slow-motion lengths (the Bomber hop ~2.2x shorter, k 2-4 packs 10-25 % longer) are not reproduced. RDE confirms both paths: in the Bomber fight (scene 266) every game frame takes exactly m vsyncs for m = 2, 3, 4 and 8 (the hop's 2 / 8 / 4 / 2 included), with no time-out; Pip's Pounce (element 293, k = 2 for 49 game ticks) takes 72 vsyncs in RDE, 2 / 3 as the rule says, and about 90 on the PS1, so its objects live a third longer there. The Time Devourer's end (lasdes2, spans of m = 4, 3, 2, 2, 1) holds over a whole pack: each span pays exactly m vsyncs per tick in RDE, the first tick after the op included, and the last sequence `kid!` starts 4995 frames after the pack's `cng1` there, 4996 in OpenCross; the PS1 pays 2.9 and 1.98 refreshes per tick in the m = 3 and m = 2 spans, so its `kid!` starts 4986 frames after `cng1`. **Presentation**: the frames `fx_slow_skip` swallows run no tick, so `BattleView::fx_slow_alpha` spreads the last tick step over the gap (m path: `fx_slow_phase_ / m`; k path: the frames waited + the frames still owed; draw only, `tick_alpha_` keeps the ticks' reads of `alpha_` unchanged). * **Timeline step** (one per task per pass, and the start step): wait -= delta. A wait > 0 ends the step. Otherwise the overshoot `carry = -wait` is taken and the wait set to 0, and while the task has ended (op 0x21 ran) the end is handled: a `loop` sequence restarts at its loop label within the step, a header-flag-bit-0 sequence with a next target restarts there (cursor + 1, the step ends), any other task is freed. Then commands run, each adding its wait first, until the sum is non-zero (a signed negative wait also stops the run); then wait -= carry, and the step ends when the result is >= 0 (exactly 0 included: the next command runs in the next step, which overshoots by the delta again) or repeats from the overshoot when it is negative. Commands that end the step themselves: 0x21 (keeps its wait; the task ends or restarts when that runs out, one step after an end with wait 0), a served 0x4D (wait 0, back to the loop label), 0x67 (pc advances, wait := 1), and a stalled 0x42 / 0x50 (pc stays, wait := 1, re-tested next step).

The later turn runs after the hop home of an engaged caster too, so the pack's own caster-framed shots see it: after a weak hit on unit 3 (bg00, Serge), a menu cast of a single-target element (1) keeps Serge at yaw 1326 through the pack, an all-targets one (29, list 3, 4) turns him to the midpoint, 1024. **A caught cast faces the range the menu selected**: the trap leaves one event on the first target (the target list reads 3 alone), but a caught all-targets summon (39 against an enemy trap) still turns the caster to the midpoint of the whole side, so `tfleaf`'s `cam0` / `cam1` (ref 1) and its wolf model's `1` (ref 8) are framed at yaw 1024 in the menu cast. A forced queue entry has no menu turn and keeps the caster's earlier yaw (1326 in the forced captures). OpenCross: `face_cast_targets` builds the facing list from the element's target spec for a caught event.
* **Enemy cast facing**: the queue executor turns the lead caster to the first target and that target back to the lead caster, for one caster and for a group (queue type 2) alike; the other listed units keep their yaw until the charge starts (below) or the pack's own Face ops turn them as they launch. A party cast turns every other target toward the caster before the caster faces the target (the midpoint of several targets, the world origin for a self target); the targets turn with the charge shot, not at the confirm, and nothing else turns at the confirm. Cast from home as the first action (bg00, Serge alone, element 1 from the top menu on unit 3, PS1): the caster already faces the target from the target select (1326), unit 3 turns 3072 -> 3374 in the frame `ch10` is selected (18 refreshes after the confirm), and a non-target enemy turned away (yaw 0) keeps that yaw at the confirm and through the cast until the facing step after the command turns it home. A PC that cast from the enemy (the HIT% menu's Element row) hops home first, and its targets turn toward its home position with the charge shot, not at the confirm: after a weak hit on unit 3 (bg00 and the three-Komodo scene, Serge), a menu cast of an all-targets element turns unit 4 to yaw 2770 in the frame `ch12` / `ch13` is selected on the PS1 and RDE, while the target it hit (3374 toward the PC either way) and every unit outside the target list keep their yaw. OpenCross: `BattleView::begin_group` leaves a PC's targets to `fx_charge_begin` (`Act::turn_targets_at_charge`), from home and after the hop home alike.
* **Camera shots with 3+ keys are cubic B-splines timed by chord length** (`BattleCamera::eval`, `spline_track`, `chord_times`): the three tracks (eye, target, H + roll) are not polylines through the keys. 2 keys are a line; 3 and 4 keys are padded with the last key to 5; every window of four consecutive keys gives 8 points (basis rows: 0 first window, 1 second, 2 middle, 3 second-last, 4 last; for 5 keys the second window is row 4; each of the 5 x 8 x 4 basis rows sums to 0x4000), the raw last key is appended; the curve approximates the interior keys. The engine's track buffer holds every interior point twice (the sample callback appends the previous and the new point; 32 entries for 3 to 5 keys); the doubled points make zero-length segments that the sampler steps over, so the pose equals that of the 17-point track (the track and pose of each `tfleaf` / `fleaf` shot read from PS1 RAM agree with `BattleCamera::eval` within 3 units). Each point is stamped with its cumulative chord length * 0x1000 / total; the master track (shot word +8 low half = 1 target, 2 H / roll, else eye) lends its stamps to the other two; evaluation lerps linearly in that time at the eased progress (0..0xFFF).
* **The hand-over kills every camera task**: the charge camera's task is unlinked, the pose registers keep their last values, so a pack with no camera op of its own holds the camera where it was at the hand-over until the next select. `BattleCamera::kill_shot` (from `BattleView::fx_charge_end`).
* **Camera task list**: the pose is driven by the HEAD of a linked list of camera tasks. A task exists only for a shot with >= 2 keys; flag bits 1-3 (`mode`) 0 / 3..7 push it at the head (the running head stays linked behind it), 1 appends it at the tail (the pose is not touched), 2 is dropped while the list is not empty. Every task ages each pass (progress += `0x40000 / dur >> 6` x delta), so a task behind the head keeps ageing; when the head passes 0xFFF it evaluates once at 0xFFF and is unlinked, and the next task drives the pose at its own progress (a newer shot does not kill the running one; a finished shot stops evaluating). The eye is ground-clamped. **An effect pack's first shot unlinks the tasks of the earlier actions** instead of pushing them back: a death cast that follows the killing blow at once (Mama Komodo, element 321 after a weapon kill) selects its `2` (80 ticks) while the attack's `atk0` (200 ticks) still runs, and RDE holds `2`'s last pose until the pack's `1` instead of returning to `atk0` (on the PS1 the pack's CD read lets `atk0` end first). OpenCross: `BattleCamera::retire_tasks` (from `BattleView::fx_begin`), consumed by the next `select`.
* **After a shot ends**: a flag-bit-0 shot (anchored to the units every tick) stops following its units at its end and the registers hold (Dash & Slash shot `6`, Gravitonne shot `3`). **Ground / radius clamps** after the chase: a shot with ref type != 0 and flag bit 4 clear sets the eye's PS1 y to 0 when it is > 0 (below the ground); flag bit 6 pulls the eye's xz in to a radius of 0x1800 around the origin. Type 22 / 23 / 4 shots take the mean box of the TARGETS' attach points, so a different hit-reaction clip on the target at the select moves the frozen frame.
* **Random camera pools**: a pack's `main` can hold several `op 0x23` groups one after the other (Aero Saucer `main` t1 {1,2} then t181 {1,3}; Fireball {1} then t185 {5,3}); each is a `rand() % n` pick, not a rule (the `trap` family's `camr` {cam1, cam2, cam3} and `cs01..cs04`, Turn `tgt0` / `tgt1`, Etrap `cam3`; "colour-dependent camera" is this pick). Comparing against a reference therefore needs the member forced first: `ours_cast34.ps1` probes the members of each unresolved pool in turn, scores them with `fx_diff.py --cam-score` (sampled reference camera frames within 64 units) and builds the `OC_CAM_PICK` list (max 5 pools). `OC_CAST_PARTY=1` limits party-side all-target casts to Serge.
* **List centroids are bounding-box midpoints**: the "centroid" of a unit list (casters / targets / everybody; Carnivore, Genie mido2, kuzira3, the `get_pos` mode 6) is `(max + min) / 2` per axis on the s16 points (C division), not the mean. `BattleFxRun::point_of`, `Helf19`, `centroid()` of summon_ports.
* **Slow-motion pacing is load dependent**: measured sequence ticks per video frame with constant k: k 2: 0.61 (0.50 in Meteor Shower), k 3: 0.38, k 4: 0.31, k 5: 0.30, k 6: 0.275, k 7: 0.23, k 8: 0.22. `fx_slow_skip` gives 2 / (k + 1) = 0.67, 0.50, 0.40, 0.33, 0.29, 0.25, 0.22: exact for k >= 5, 10-25 % fast for k 2-4 (the PS1 loop iteration costs 2 vsyncs in a heavy pack). The lead accumulates inside slow-motion packs (Meteor Shower hides the units at frame 443 against the PS1's 472). The per-iteration cost is not a constant (pack load, and the closing wait's CPU-time time-out, see **Slow motion** above); OpenCross keeps the one-vsync rate.
* **Freefall 43acce**: 0x180 and the fall after the peak use `v -= 5` per tick (0x182 uses 10, but the pack's op 0x182 only fires late); the rise of 386 units/tick peaks after 77 ticks at y -15276.

## 10. Engine rules established by comparison with the PS1

### 10.1 Emitter and sequence engine
* **Every emitter start goes through one spawn path**: a header fire, a death child (`ON_DEATH_SPAWN`) and a periodic child (op 0x3C) all run the spawn and then emit the op-0x45 (SPAWN_WITH) child at the new object's position. A SPAWN_WITH emitter reached only through a chain must therefore still spawn (Ice Blast `ice1 -> ice2 -> ice3 (SPAWN_WITH p101)`, `p101 -> p102`). OpenCross: `die()` / `periodic_spawn()` call `fire`; nested `die` adds no depth step of its own. A death child skips the object step of the frame that spawned it (`room_effects.md` 3.5).
* **Death children turn by the dying object's op-0x39 basis** (`room_effects.md` 3.5): the first op-0x39 record of the dying object's header (not of the child's), without its scale bits, is the children's parent basis, at the dying position with object flag bit 19 and at the origin without it; a bit-15 dying object without bit 19 hands a child without bit 15 its position turned by that basis. Visible where the basis is turned and the child has parent-relative ops of its own: element 29 (37comet) `sh21` / `sh23` -> `sh22` and `sp21` / `sp23` -> `sp22` drift along -x (velocity (-32, 18, 0)) at the dying meteor's z, element 253 (oodama) `*-0` -> `*-01` take the basis translation (bit 19) at the dying height; Thunderstorm's (thndr) `tam3 -> tam4` (bit 15) and `tam6 -> tam8` (bit 19) run with the identity basis, so their children do not move. OpenCross: `die()` builds the basis and passes it to `fire(header, basis)`.
* **Sequence ops 0x55 (emitter stop) and 0x5A (emitter kill) read their name at +8** (not +12); a zero name makes the op a no-op. 0x55: for every header of that name unlink it (if not yet stopped) and set its bit 0, then walk the heap: an object of the header with **life == 0 is freed, any other gets life := 1** (it dies on its next step, death child included). 0x5A frees every object of the header at once.
* **Sequence command names keep byte 0x7F**: eight packs name a started emitter with a DEL as the 4th byte (`9boll` `hi2` x2, `36shu` `12`, the six Turn spells' `wa0`). The registry compares names as a u32, and the emitters' own names carry the same byte, so the name must not be filtered to printable characters (`room_effects.cpp` filter `ch < 32`). Dev logs print non-printable bytes as `.`.
* **Spawn jitter**: `countdown := period + 2 * (rand() % jitter)` with jitter = header flag bits 3-8 (the field overlaps the bit-4 flag); the header fires when `--countdown == -1`, i.e. every `period + 1 (+ 2 r)` ticks. Per-wave count differences between two runs with a jitter field are RNG, not a rule. Dev: `OC_FX_START=1` prints `fx header <name> start dur period repeat jitter flags`; `OC_FX_SEED=n` sets the pack's emitter RNG seed (default `1 + casts`).
* **Per-target clone headers are named `sado`**: a clone made for op 0x22 / 0x2F inside a per-target loop with target index k != 0 gets the name `sado` (4 bytes `73 61 64 6F`). OpenCross: `EmitterSystem::start_for_target` names the clone `sado` (`Header::alias`, `nm()`); every name lookup (`find_header`, hooks, `layer_on` / `layer_off`, kill-by-name) goes through it.
* **A group cast charges every caster**: after starting the charge file `ch0<colour>` for caster 0, the host walks acting-list entries 1.. and for each clones the charge sequence with the clone's caster index i (op 0x45 `s16@10 := i`, 0x46 / 0x57 / 0x59 ... as in 9, "Per-target loops").
* **Every caster holds the cast pose through the charge**: each unit of the acting list (a double or triple tech's participants, a monster group cast's members) runs S5 entry 5, whatever its place in the list: X-Strike chosen by Glenn lists Serge first and both take the pose. When a caster's entry-5 script ends, the clip it left (13, the cast loop) plays on: like the actor, no caster goes back to its idle before the action releases it. PS1 (scene 7): every participant plays clip 13 from the charge start to the hand-over, 90 to 108 refreshes for X-Strike, Flamenco, Dragon Spike and Z-Slash, 126 for Delta Force (OpenCross 101-112); the two casters of Bakunage (434, scene 268) hold it the same way. `BattleView::fx_charge_begin`, the `held` test of the unit pass (`battle_view_units.cpp`).
* **Freeing a light object clears its slot** (the slot intensity := 0), so the next light's slot search (first slot with intensity 0, else slot 2, then free the older live light of the same sprite on that slot) sees it free.
* **Header words +8 / +0xC (frame / countdown) are meaningful for a header that waits and is never started**: unico `pou0` (a periodic child) stores frame 116, which the oscillator ops read as time, so SCALE_ADD_OSC / SCALE_RATE_ADD_OSC give a head several times larger than from a zero start.
* **Zero-scale objects collapse**: object flag bit 22 (0x400000) is set when the scale is not the default (0x1000 x3); the matrix is then rebuilt every tick, so a scale of (0, 0, 0) gives an all-zero matrix and the sprite has no extent (Earthquake's `tget` anchor particle). A zero scale must not be skipped.
* **Sheet animation**: when the frame lookup finds no frame `+0x7A` it sets `+0x7A = 1` and draws frame 1, so animated sheets (den*, piri, kona ...) loop; OpenCross wraps `Object::frame` in the update. A replaced draw callback that re-does the integration (Ice Lance) must use the object's position shift, not a literal 3 (`ObjectRef::shift`).
* **Type-20 model textures**: two pages are baked (CLUT row `clut_y` and `clut_y + 1`); the face CLUT bit picks the second (`model.md` 3.3 rule 4): Sonja's wings (`ee97`, row 239) are lime, not row 238 orange-brown.
* **Sprite packet drop rules**: RTPT on three corners then RTPS on the fourth: only the last projection's flags decide; flag bit 31 (overflow, depth outside 0..65535, `H >= 2 * SZ3`, SX2 / SY2 outside -1024..1023) drops the packet and ends the object's sprite loop; the first three vertices only saturate SX2 / SY2. The GPU skips a triangle whose vertices span > 1023 in x or > 511 in y (native 320 x 224 pixels). `EmitterSystem::draw` implements both (corner 4 with `vz < 1` also drops the object).
* **An op-0x48 callback REPLACES the object's draw**: it stores the record's callback as the draw function the object loop calls (as the sprite types' stock draws are installed). Ice Lance's callback ends in the stock mesh draw; Gravitonne's `hole` particles are hidden by it (the PS1 draws no purple circles there).
* **Hit sparks by name (anmseq op 0x1D)**: the op walks the whole effect registry for the literal 4-byte name and starts every type-0x0A header of that name; there is no hit-class gate. The class lives in which name the reaction script uses. A monster's element pack carries its own hit sparks (`0s00` / `0m00` / `0l00`: renkeri has only `0m00`, elf3ren s + m, sid_tuki all three). During an element pack the registry holds the pack, the resident `battle.prd` and the party's resources, not a monster attacker's own `at0` (it is looked up per resource group at that attacker's own attack start). The reaction script is the pack's type-0x1A `main` run on the target with variant 7; hit class 0 / 1 / 2 selects `0s00` / `0m00` / `0l00`. A header with no match in the registry starts nothing (Just 4 Kicks: kicks 1 and 3 find none, kick 2, the knock-back, sparks `0m00`). The headers are searched first in the unit's own anm bank, then in the running pack's headers of that name, which start in a second anm bank keyed by the pack (`pack#<eid>`, the pack's own sheets). `BattleView::anm_effect`.
* **A unit's at0.prd timelines** (a heavy hit's: Guile's `all1` / `all2` / `all3` in the nested drps `fir1..3`, started by its atk script's op 0x68 / 0x7D) start the unit's own emitters by name (op 0x22) with the timeline's target: a per-target repeat (header flag bit 0) serving target k > 0 starts a clone whose op-0x39 selectors 1 / 2 read 9 / 0xD + k, and its op 0x2F child serves the same target, so a sweep fires one projectile per enemy (`all1`: `w`, then per target `pt` and the child `lv1` = `ft1`, `ft0`, 22 ticks later the impact `bh ` on the target and `lt1`). The op-0x39 basis of these emitters is the effect packs' one: selectors 1 / 9 the actor, 2 / 0xD target 0, 0xE..0x15 targets 1..8 of the target list (ascending), 10 / 11 acting-list entries 1 / 2, 3 / 4 / 5 the acting list / the target list / every unit and 0x16 / 0x17 the target list on the ground (y 0), a list giving the midpoint of the bounding box of its units' points ((max + min) / 2 per axis) and the mean of their yaws, at attach point `joint - 2`; with a second point the look-at basis (local +X from the first point to the second, X / Z scaled by the distance / 2048, origin at the midpoint), so `ft0` (point 1 / joint 22 to 2 / joint 18, start x -928, velocity 2864 over 22 ticks) flies from the rod's tip to the target. Its sprite `maru` is a type-14 mesh of the resident `battle.prd`, drawn through the stage pipeline like a pack's resident meshes. PS1 (scene 7, Guile's heavy hit on three enemies): the orbs reach all three, which react on the same frame, 27 refreshes after the React; OpenCross 24. `BattleView::anm_effect_for_target`, `anm_point`, `anm_draw_meshes`; `BattleCamera` runner `inherited`.
* **Thrown weapons are a unit emitter drawing the weapon mesh**: a boomerang's flight is not the mounted slot moving. The atk script hides the mounted weapon (op 0x7A) and in the same tick starts, with op 0x1D at the throwing hand (attach 7 / 8, mode 1), one of the unit's own at0.prd emitters whose op 05 sprite is type 14 named after the thrower's two-digit character number, the name under which the battle registers the PC's equipped weapon mesh (`model.md` section 7). Its op 3E path (a type-0x18 curve of the same at0.prd: `?hp0` for `?yok`, `?hp1` `?dwu`, `?hp2` `?upd`, `?hp3` `?all`) carries the mesh out to the target and back while ANGLE_RATE spins it. The curves' basis bytes are the thrower's hand (selector 1, joint 9 for the `r` curves, 0xA for the `l` ones) looking at a second point at joint 0x12: target 0 (selector 2) for `?hp0`..`?hp2`, the targets' point (selector 4: the bounding-box midpoint of every target of the attack's target list) for `?hp3`, so the heavy throw, which strikes every enemy (`rules/battle.md`, weapon sweeps), loops around the whole group; op 0x79 shows the mounted weapon again about when the object's life runs out. Mel (`mell`, "34") and Van (`banc`, "36") have `ryok` / `rupd` / `rdwu` / `rall` (right hand) and the same four `l...` (left hand), object life 60 for `yok`, 80 for the others; the atk script picks one per strength: Mel weak `ryok` (mounted weapon hidden from script tick 20 to 80), medium `lupd` (32-112), heavy `lall` (40-120); Van weak `lyok` (20-80), medium `ldwu` (28-112), heavy `rall` (40-116). Harle ("22"), Luccia ("11"), Sneff ("37") and Doc ("39") have `r0` / `l0` (life 16, no path). PS1 (scene 6, Van alone, weak hit): the `lyok` object at life 58..3 against OpenCross one tick apart follows the same path within 21-176 units (mean 58) over a 3400-unit round trip. PS1 (scene 7, Van alone against three enemies, heavy hit): the `rall` object at life 77..2 against OpenCross follows the same loop within 290 units (mean about 200) over a 4600-unit round trip. `BattleView::anm_draw_meshes` -> `fx_draw_weapon_meshes`, `game::weapon_mesh_character`.
* **Unit model S6 DRPs are resident**: when a unit model loads and its S6 DRP is non-empty, its entries are registered as resident files. Of the 44 monsters' models only 5 carry type-0x0A spark headers: `torimeca`; `ki` = Family Tree 102 (`ueru` x2, named by its S5 entries 13-16 at attach 8 / 7); `q_con2` = Bulb 167 (`k000` x2, S5 entries 13-16, attach 14 / 27 / 16 / 2); `bom` = Bomber 195 (`fire`, `hiba`: `hiba` in S5 entries 14-16 at attach 31, mode 0x81, plus shot / sequence / sound `bom0`); `sfin` = Sfinx 139 (`sfin` x3, named by nothing: dead data); see `ocbattle fx-reg --s6`. These are played by the battle scripts' `play_anim` / `play_anim_of` cutscenes (ops 0x58 / 0x5A), not by an `atk` cast (10.5). The others' S6 holds camera shots `mag<k>` / `big<k>` and sequences `mag<k>` only (the monster's own charge camera timelines, one picked by `rand()` from the model's S5 entry-5 script `7D "lvs3" | 7D "lvs1" ...`). They are camera shots, never listed as `fxseq`. S6 shots and timelines are resident registry entries: the Camera (`C2`-style by-name shot, anmseq Camera op) and Sequence (anmseq 0x68 / 0x7D) events of a script that runs with no action of that model look the name up in the present units' S6 banks when the active bank misses it (Family Tree `hanl` timeline and shots, Bomber `bom0`).
* **Hide bit across packs**: a pack end leaves the hide bit; the idle restart shows a living unit again, a dead one stays hidden through the next pack (the tank hidden by its 329 stays hidden through 349).
* **An enemy's death fade belongs to its reaction script**: nothing else starts it. The rules' KO (hit resolved with HP at or below 0) sets the model's dead flag at once; the `dead` branch of the reaction (variant 7 of the pack's or the attacker's table, entry 0x80) plays the death clips, then, on a monster, the 0x8E soft fade over 32 ticks and ModelShow 0. The pack end holds for that script, so the fade always plays out. A reaction without this branch has no fade: `kill` (element 349) is Damage, a wait and the idle tail, so its dead targets stand on clip 8 while they leave the alive mask, and they stay there. A kill that no reaction script takes has no fade at all: the enemy keeps the clip it played, visible, with the death flag, and the pack ends skip it. PS1 (scene 6, Serge's weak hit on one pup registered so that the weapon attack's resource is open, then Aqua Beam queued from Serge on the other pup at 1 HP: the reaction plays on the first pup, `docs/validation.md` section 3.4): the second pup takes the KO and the death flag at the resolve and no script, no clip and no soft fade in the next 6000 refreshes; the same with Ice Blast queued from the first pup. A killing cast normally runs a reaction on its target: on the PS1 Aqua Beam, Ice Blast, Gravity Blow, Freefall, Volcano and the summons Genie, Golem, Thunda Snake and Grim Reaper on a pup at 1 HP all did (the summons' late in their pack, then the soft fade), and in OpenCross every damaging element cast on a pup does when a tech is cast by its own casters. A double or triple tech's reaction comes from its participants' scripts, so it needs all of them: Dragon Spike (145) cast by Karsh and Zoah from the menu (PS1, scene 6, the pup at 900 HP) plays the pup's reaction from 180 refreshes after the cast pose, clips 6, 7, 8, 14, 8, 14, 8, 9 and 1; OpenCross 171 ticks after it, the same clips. Some packs run no reaction at all: Giddy Breath 464 (`bre_gal.prd`, a Gurgoyle in scene 331) takes 2 HP from Serge with no script on him at the resolve or after, on the PS1 as in OpenCross, while Giddy Breath 496 (`bre_ye.prd`, a Centaurpede in scene 258) plays a reaction on its target.
* **The death flag restarts nothing**: a kill sets it when the action resolves; only a script that runs on the unit (the killing hit's reaction, a later hit's, a revive's table) changes the pose, and the pack end restarts only units without it. A PC killed by a hit that no reaction script takes stands on in its idle clip; a member knocked out by its save record has the KO bit without the flag and stands in the low-HP stance until the first hit pass of the fight gives it the flag, and then on unless a reaction runs on it (`docs/rules/battle.md` 1.2, the death flag in 6.3, 6.5). The poison step's KO is the one that restarts the idle, at the resolve, for every PC it knocks out but the one whose command issued the action (`docs/rules/battle.md` 2.4); an attacker it knocks out at its target still hops home, and the return's end lies it down. That step also shuts the PC's eyes, takes its face flag and writes its idle-pose word 8 (the eye rules: `docs/rules/battle.md` 6.3, the knocked-out pose).
* **A knocked-out PC is not darkened.** Its model colour stays 0x80 for as long as it is down, and nothing else (light, back colour, semi-transparency, palette) changes on KO: the death clips are the only change, so a fallen PC lies at the same brightness as a standing one, in both art modes. Only the enemies fade (above).
* **HP a script wrote to 0 is not a KO** (op 76: Solt and Peppor in the Hi-Ho Tank's kill script, scene 425): the kill script still runs and op A6 takes the unit out of the alive mask, but the dead flag stays clear, so the unit neither plays death clips nor fades and the pack end restarts its idle like a living unit's. The low-HP bit (HP at or below max / 4) is refreshed when the next action resolves, so from the end of that action's pack the unit stands in its low-HP idle (clip 10 on the Dwarf).
* **Revive's get-up table**: `white/107revi.prd` (Revive, element 94) carries a type-0x1A table `getu` (one entry, variant 7) that its sequence starts on the target: SetAnim 9 (the get-up clip) blend 8, flags 0xC008, a wait for the clip's end, then the idle's pose pick. It is the only `getu` on the disc; Full Revival (`108retu.prd`) has no type-0x1A table. The order against the revive's death-flag clear is in `docs/rules/battle.md` (knocked-out pose and revive).
* **A reaction script that ends restarts nothing**: the end op (0x00 / 0x3E / 0x4C) of a reaction on a unit outside the acting list leaves the clip the script set last looping, and the idle script does not start. What re-picks the pose is the next idle restart: the effect end hook, which after an element action (and only then) starts S5 entry 11 on the first unit of the acting list and then restarts the idle of every unit without the dead flag (so entry 11 plays only on a dead first caster, `docs/rules/battle.md` 6.3), starting even the clip the unit already plays again with the idle's blend (16); the command menu re-entry for its PC; Defend; the thaw. A weapon attack's pack end restarts nothing, so a unit hit by a weapon keeps its reaction's last clip into the next restart. A reaction's tail picks its own pose (the guard pose, the low-HP clip 10 or clip 1, from the control flags), and the low-HP bit is not cleared by the dead bit: a PC killed by the first of three hits ends the reactions to hits 1 and 2 on clip 10. PS1 (scene 6, Serge, Kid and Alf; casts forced from Serge on the menu's first frame, times in refreshes from the resolve): Fireball on Kid at full HP, reactions at 231 / 263 / 342, each ending on clip 1 blend 16, then nothing until the pack end at 444 restarts every living unit on clip 1 blend 16; the same on Kid at 1 HP, hits 1 and 2 end on clip 10, hit 3 plays clips 7, 14 (blend 28) and 8 (blend 12) and Kid lies on clip 8 with no restart; Revive on Kid, get-up clip 9 at 249, clip 1 at 303, the pack-end restart at 338; Serge's weak hits on a Komodo Pup (clips 5 or 6, 16, then 1) and a killing hit (5, 10, 7, 14, 8), and a pup's hit on a guarding Alf (5, 16, then the guard clip 21): no idle restart in the next 1000 refreshes. OpenCross: the reaction's end sets the unit idle without starting the idle script (`BattleView::tick_units`), the pack end restarts every living idle unit with `start_idle(unit, true)` (`fx_end`, `Visual::idle_reblend`), also a caster or target whose pack script has already ended (PS1, Serge's Tablet in the three-PC room-53 battle: the caster's own clip 1 two refreshes before the pack end, then clip 1 blend 16 on all three PCs at the pack end and again on Kid at the menu re-entry 17 refreshes later), `fill_ctx` keeps bit 31 beside the dead bit. The menu re-entries are listed in `docs/rules/battle.md` section 3.4.
* **Colourless casts have no charge**: an element whose colour bits are 0 or all six opens no charge file: no chant, no S5 entry 5 (the casters stay in their idle) and the pack is released at once. Elements 341, 349, 452 and 526 are of this kind.
* **Charge start facing**: as a charge starts (a Pterodact combo has none, so its target stays turned to the lead caster and the second caster keeps its yaw) every listed target turns to the midpoint of the casters' bounding box, then every caster to the midpoint of the targets' (the camera frame of anchor type 3, the casters' mean yaw, follows). This holds for one caster as well: a monster casting on two units looks between them and both turn to it, and a unit standing on the midpoint it should face (a self target) turns to the world origin. Stock ops that name the casters walk the whole acting list: 0x76 sets every caster and target to yaw -0x400 at x < 1, else 0x400.
* **3voice op 0x100** (Hi-Ho Chorus): `u32@+8` is a type-0x10 sequence tag (zero = nothing starts), `s16@+12` an acting-list entry; the sequence starts bound to that entry. The pack calls it for `kemu` and `shut` on entries 0..2. Its emitters run as `sado` clones.
* **Script-actor list (battle op 0x86 `camera_target`)**: the entity slot is `(arg + 0x21) & 0xFF` (arg `0xE9` = self), not `arg + 1`; it rewrites the acting-list head (entries 0..6 := none, entry 0 := that unit). Selectors 1 / 9 of anmseq emitter op 0x39 and `GetPos` list 0 read the acting-list entry 0, so after a script's `camera_target` they resolve to the cutscene's unit (Bomber's `hiba` header = op 0x39 selector 1, joint 33); without one the last action's actor is used. OpenCross: `script_actor_` (set by ops 0x7A / 0x86, reset by the next command setup) wins over the action's caster list (`BattleView::script_list_unit`, `anchor_frame`, `anm_start_system`).
* **All-zero attach record**: an attach record that was never filled (point 25 of a 25-point model) is joint 0's origin, not "no point" (`UnitPose::attach_or_root`, used by `fx_attach_unit`).
* **Monster-cast traps** run `montrap.prd` (eid 397), not `etrap` (396) / `sumtrap` (395): `main` = MARK, CHILD_SEQ(cam), ENEMY_B_FN, flashes, LOOP_LABEL, CHILD_SEQ(`tgef`), NEXT_TARGET_LOOP; `tgef` starts the colour ring emitters. `BattleView::fx_begin` maps 395 / 396 to 397 when the caster is not a PC. The PS1's mode-5 element handler picks 397 whenever the caster is an enemy slot; on the shipped data that is the same rule, since all 18 mode-5 records carry 395 or 396 and no other record does. There is no monster-specific pack for status spells (83 -> `94manf` for both casters).
* **Host init of `sky` (162 Flying Arrow)**: the stock `main` tail plus a type-0x14 `act0` / `act1` model and the `bus` table; `sky` is in `kMainTail` (`battle_view_fx.cpp`) so `cam0` / `strt` / `jump` / `wp00` / `hit` / `hit1` / `ya00` start.
* **Pack close is not always the end of `main`**: Fire Pillar's `main` ends at tick 420 but the light `koug` (LIFE 324) and the damage digits continue; the PS1 pack closes ~45 ticks after `main`. Unknown: what delays the close (a battle-script wait on the hit / damage).
* **Pack end** is the last sequence's end. **Emitter counts at the same pack tick may differ by +-2 per emitter** between two runs from sampling phase (period 1, repeat 1 emitters), which is not a rule difference.
* **Anmseq op 0x44 reaction vs op 0x48 CallDamage**: an enemy's KO fade is the tail of its reaction script, not the lethal CallDamage; the target holds idle clip 1 / colour 128 until the op 0x44 reaction.
* **SetPos is immediate inside a script run**: the model position is written at once, so a LookPos in the same tick reads the new point. `Vm::tick` keeps a working copy of the context position that SetPos updates for the ops after it (units and pseudo-actor alike).
* **RotateT turns x and z too**: op 0x11 steps the shortest signed difference of all three 12-bit angles (x at +0xA4, z at +0xA8, yaw at +0xA6) by `(diff << 12) / n` per tick, no snap at the end (an exact half turn of the yaw, 0x800, goes the negative way: Run Away's turn from 0x400 to 0xC00 passes 0); the battle model matrix is `RotMatrixZYX(x, yaw, z) = Rz * Ry * Rx`, then scale.
* **CallDamTarget / CallDamTargetAll** run the target's variant-7 entry on every target except the model running the host script: a React op never gives the variant-7 reaction to the calling model. A death cast aims at the dying unit itself, so its own script keeps running.
* **CallDamage (anmseq op 0x41) lands the calling model's own result**: the model is looked up in the target list, then the acting list, and the number, HP change and flash come from that entry's result for the running action. An acting unit nothing hit has no result, so nothing shows. * **Head look-at (anmseq ops 0x88, 0x89)**: `88 list idx point` stores the world position of attach point `point` of the list's entry (0 the acting list, 1 the targets, 2 a unit number) as the running model's head target, starts a per-tick task that copies that point into the target again every tick, and installs the head-turn callback on the model's head joint (attach point 1's joint) at rate 0xE00, the field's head turn (`model.md` 6.4): the joint is built from its rest local turned by `RotMatrix({ax, 0, az})`, the start direction is the model's forward axis, x clamped to +-0x200 and z to the range of the target and current angles within -0x180..0x200, one step per elapsed tick. `89` frees the task and sends the target 0x1000 straight ahead of attach point 1 (the model's -z); the callback goes once the head has settled (a change below 0x40 / 0x1000 on x and z). The battle model's world matrix is its rotation only (no entity matrix). Only `monster/konsin.prd` (element 335, scene 477, a group cast of unit 4 with the acting list [0, 4], the leader drawn as model 51 `yamaneko`) uses them: `88 0 1 1` turns the leader's head toward the face of acting-list entry 1 (unit 4), `89` 180 ticks later; unit 4 runs no head turn. * **Texture rect flip (anmseq ops 0xA2 - 0xA5)**: `A2 x y w h` / `A3 x y w h` store rect A / B (x, w in VRAM halfwords, y, h in rows) in one battle-wide setup; `A4 sel idx d` sets the destination to the texture page of the model of entry `idx` (sel 0 the acting list, else the targets) plus `d & 0xFF` halfwords and `d >> 8` rows; `A5 t0 t1 total` copies that setup into a task which, on its first tick, copies rect A onto the destination, then B after t0 ticks, A after t1 more, and so on, until `total` ticks have passed.
