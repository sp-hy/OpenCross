# Movies: which FMV a field script plays (op 7E / D4), file names, play range

This document covers how the field-script movie ops (`7E U` PLAY_MOVIE, `D4 U x` PLAY_MOVIE_SKIPPABLE; `7F` WAIT_MOVIE only waits for the end) choose a movie, how the movie number maps to a file in the remastered `movie.dat` archive (Bink 2, `.bk2`), which rows play only part of a file, and how OpenCross plays, ends and pauses a movie. `ocmovie table` lists everything below from the game data.

## 1. The operand is a table row, not a movie number
`7E U` and `D4 U x` read **row = low byte of U** and index a table in `field.prg`: disc 1 holds rows 0..23, disc 2 holds the following 13 rows (the same array continues). Row layout (0x18 bytes):

| off | field | meaning |
|---|---|---|
| +0 | start | frame offset used by some rows (section 4) |
| +4 | 1 | |
| +8 | end | frame count: the file's own frame numbers (STR frames = Bink frames; 15 fps, `ending_s` 30 fps) |
| +0xC | mode | 0, or 3 / 4 for the two ending_s rows (disc 2 rows 11 / 12): the staff-roll layout (section 4) |
| +0x10 | **movie number** | |
| +0x14 | volume | 0x7F full, 0x6E on row 0, 0x50 / 0 on a few rows |

The operand is not the movie number. Rows 1..15 happen to be the identity, but row 0 is number 19 (the opening `newop`) and rows 16..23 map as 16 -> number 0 `a07b_ite`, 17 -> 16 `b17opkid`, 18 -> 17, 19 -> 18, 20..23 -> numbers 7 / 5 / 15 / 16 again. The title room (`opening.bin`) plays `D4 #0` on disc 1 = the opening FMV `a01op` (the logo scene appears when it ends or is skipped) and `D4 #1` on disc 2 = `titleb`. OpenCross: all rows are in `src/game/disc_index.cpp` (`DiscIndex::movie_row`).

## 2. Number to file
The movie's file index is **6035 + number** in the `.fnd` of the disc in the drive (`cdrom.fnd` disc 1, `cdrom2.fnd` disc 2; the record is `c:\movie\<name>.stv`). The disc is variable 0x42 (disc - 1) / the DiscCheck (`FieldWorld::disc()`). Disc 1 rows address the 20 disc-1 records (numbers 0..19), disc 2 rows the 11 disc-2 records. A record that is not `c:\movie\...` plays nothing.

Name to archive member: `movie/<name>.bk2`, except the three per-language movies: `newop` -> `a01op_<lang>`, `b28end` -> `b28end_<lang>`, `final` -> `final_<lang>`, suffix `en fr it de es jp`. `movie.dat` holds 46 members (stored, not compressed): the 6 languages of those three, `ending_s`, `title`, `titleb` and the other `a..` / `b..` movies. OpenCross: for each stem, `<name>_<lang>` is tried before `<name>`, and at each stem a mod's loose `.mp4` / `.mkv` before the `.bk2` (`movie::resolve_member`); the language comes from the config, so a mod may localise any movie.

## 4. Play range
Table frame numbers are the file's own 1-based frame numbers, at its own rate (15 fps, 30 for `ending_s`; never rescaled): playback starts at `max(start, 1)` and stops when frame `end` (clamped to the file's frame count) is reached, so frames `start .. end - 1` are shown. A row without a range has end = the frame count: its last frame is not shown either. Only some rows give a range:
- disc 1 row 20: start = 1 + 0x131 = 306 (not the row's own start field), end = row end (489);
- rows 21 and 23: start = 1 + row start = 1 (the beginning), end = row end (90 / 258, shorter than the file);
- row 22: start = 1 + 0x118 = 281, end = row end - 10 (417);
- disc 2 row 12: start 1, end = row end (8130 of `ending_s`'s 8951 frames). Every other row plays the whole file.

OpenCross: `DiscIndex::movie_range` returns the range; `movie::Player::open(..., start, end)` turns it into 0-based decoder frames `[start - 1, last - 1)`, `last` = `end` clamped to the container's frame count (`Decoder::frame_count`; 0 = the frame count), decodes and drops the frames and audio before `start` (clock and audio start there) and stops at `last - 1` (audio is cut at the same time). A mod movie that replaces a ranged row must keep the original's frame numbering.

**Volume.** RDE starts every row's Bink sound at `vol / 127` of its movie volume; OpenCross scales the movie's sound by the row's `vol / 127` on top of the movie bus (`Mixer::movie_start(level)`): 110 for the opening, 80 for `final` and the two `ending_s` rows, **0** for disc 2 rows 2 (`b28end`) and 3 (`final`), which play without sound.

**The music keeps playing.** Neither the PS1 nor RDE stops the field's song for a movie: the PS1 movie loop suspends the music only while the CD stream runs dry (a stall, not the movie), and RDE replaces the stream routines with Bink and never touches the music. A script that wants silence stops the song itself (`88 FF` or an `FE 1D` fade before the `7E`). The true ending relies on it: opa_b04f (entrance 2) starts song 7, fades it in over 90 frames and plays disc 2 row 2 (`b28end`, whose Bink track is digital silence) under it, then fades the song out after `7F`. OpenCross leaves the BGM alone while a movie plays (`App::start_movie`); only the pause screen holds it (`Mixer::hold`).

**The staff roll (disc 2 rows 11 / 12, modes 3 / 4).** `ending` entrance 1 plays row 11 (the whole `ending_s`, last frame 8951); `opa_a04f`, `opa_b04f` and `ryu_b28i` play row 12 (last frame 8130). Both show the movie in a small panel and a credits strip that scrolls up beside it. RDE (the reference; frame grabs of the whole roll, the layout is the same in every frame):
- Picture = the 4:3 fit of the window (height min(h, w * 3 / 4), centred), without the crop bands. **Movie panel**: x 0.48 .. 0.97, y 0.46 .. 0.95 of it (0.49 of the picture each way, the whole 640 x 480 movie scaled into it); black elsewhere.
- **Strip** image: `hd/staff/staff24.png` in Japanese, `hd/staff/staff24us.png` in every other language (English, French, Italian, German, Spanish), 144 x 8950 RGB, white names and lilac headings on black, content rows 225 .. 8691. It is drawn on RDE's 1280 x 960 canvas over the game viewport (`render::overlay_fit`: 8/960 bands, the rows squashed by 944/960 x 928/960): x 0 .. 0.45 of the canvas width (576 units, 4 per strip pixel), y canvas 0 .. 960, i.e. window y 0.0083 .. 0.9589 of the picture. The area shows span = 144 * 3 / (8950 * 4 * 0.45) of the strip's height, 240 rows. Linear filtering, the movie's alpha (1 while it plays). The strip, the panel and their placement are the same in both art modes: RDE draws the PNG with original art too (the PS1's own strip, streamed with the movie, is Japanese only), so OpenCross's Classic mode uses it as well.
- **Scroll**: the strip row at the top of the area, as a fraction of the strip's height, is top = (span * 0.52 + 1) * F / last - span, F = Bink's frame number while frame F - 1 is shown, last = the row's last frame (8951 / 8130). At frame 0 the strip's first row sits at the bottom edge; at the last frame the strip's end stands 0.52 of the span above the bottom, past the last credit. Row 12 therefore scrolls 8951 / 8130 = 1.10 times as fast as row 11, about 1.01 strip rows per frame on row 11.
- The PS1 (DuckStation, Japanese disc 2) builds the same picture in 24-bit colour on a 208-line display: the strip rows come from the STR's data sectors (0x1B0 bytes = 144 pixels each), kept in a 272-row ring that moves one row per movie frame while the stream has rows buffered, one row per display line over the left 144 of 320 pixels (0.45); the movie panel stands higher than RDE's, x 0.47 .. 0.97, y 0.36 .. 0.87 of the 320 x 240 output. RDE's data has no STR, and its PNG rows are those strip rows (the same picture in a DuckStation grab, which scales the 224 lines to 240), so OpenCross uses the PNG and RDE's layout in every art mode.

OpenCross: `App::start_movie` switches a mode 3 / 4 row to the layout (`movie::Player::set_staff_roll`, the strip from `movie::staff_strip_member(language)`); `Player::draw` puts the movie in the panel and the strip (`staff_strip_top`, clipped to the strip's rows) on the overlay canvas. The held last frame (section 6) is the panel only: by the last frame the strip is past its last credit. RDE picks the layout by size (a movie smaller than its 1280 x 960 render size, which only `ending_s` is); OpenCross by the row's mode, so a mod's upscaled `ending_s` keeps it. Route `staff_roll` (`set var 42 1`, `load ending 1`).

## 5. Decoder and file access (OpenCross)
Bink 2 is decoded with librempeg (built locally by `scripts\build-librempeg.ps1`, commit pinned in CREDITS.md); audio is pulled from the same stream. YUV->RGBA runs on the decoder worker thread; the frame texture is created at the movie's own size.

- **Streams.** The first video and first audio stream are used; a movie without audio plays against the wall clock. Frame time = decode index / frame rate (`avg_frame_rate`, else `r_frame_rate`, else 15), not the container timestamps. Video decodes with automatic codec threading.
- **Mod codecs.** Besides Bink (`.bk2`), mods may supply HEVC or H.264 in `.mp4` / `.mkv` (any codec librempeg decodes; the file name is the container hint). Accepted pixel formats: YUV 4:2:0 / 4:2:2 / 4:4:4 8-bit, full-range 4:2:0 (YUVJ), 4:2:0 with alpha (alpha plane copied to RGBA alpha), 4:2:0 10-bit (shifted to 8); anything else logs an error and drops the frame.
- **Colour.** Bink is always full-range BT.601. Other codecs follow the stream tags: JPEG range = full, else limited; BT.709 / BT.2020 NCL = Rec. 709, untagged = Rec. 709 from 720 lines up, else Rec. 601.
- **Audio.** Float samples (packed or planar) only; mono is duplicated to stereo, channels above two are ignored, and the stream is resampled by linear interpolation to 48 kHz stereo float (`Decoder::kAudioRate`).
- **Pacing.** The player keeps up to 8 decoded frames and about 1 s of audio ahead. The clock starts once the first frame and 0.25 s of audio are ready; it then follows the mixer's consumed movie sample count (never going backwards) and switches to the wall clock once the audio is drained. The movie ends when the decoder is drained, the queue is empty, one frame period has passed and the audio has played out. A movie that cannot be opened is skipped and the script continues.

**Mod movies stream from disk.** A `movie/<name>.bk2` supplied by a mod is a loose file (often hundreds of MB, e.g. 1280x960 or 1920x1440 upscales). `Player::open` asks `Vfs::loose_file(member)`; when the overlay resolves the member to a file on disk, `Decoder::open_file` reads it through a buffered, seekable file AVIO (no whole-file read, no start stall, no RAM copy). Archive members (`movie.dat`) go through `Vfs::read` + `Decoder::open` (memory AVIO). The member name is resolved with `exists()` (overlay first), localized `_<lang>` before plain, so `a01op_en.bk2` etc. are found.

`FieldWorld::play_movie` logs a warning when a second movie is requested while the first is still requested or playing.

The retail player has two playback loops, picked by 7E's high operand byte or the low two bits of D4's flags; every 7E and D4 in the data picks loop 0, and OpenCross has one loop and ignores the selector. The loop 1 runs the field's frame driver once per movie frame with the field picture off: the logic half runs (entity scripts, movement and triggers, the screen fade, camera scroll), the picture half does not (animation requests, background layers, models and shadows, effects, dialogue windows); the movie's own room sequence (`mo1?` / `mo2?`, `room_effects.md`) runs alongside. Every one of the 48 `7E` / `D4` ops in the scripts is followed directly by `7F WAIT_MOVIE`, so the calling script stands still; only other entities' scripts and a running fade advance. OpenCross ticks only the room sequences during playback (`FieldWorld::movie_tick`).

## 6. Movie end: hold or fade the last frame over the resumed field
Retail PS1: the movie loop of op 7E / D4 fades during the last 8 frames, then rebuilds the field display and the script continues in the same frame: no black gap, no load between the movie and the next scene.

RDE (the reference) plays the movie with Bink and decides at the end frame by **flag 8** of the movie flags: `D4` takes them from its second operand (every `D4` in the data has `#8` or `#520`), `7E` sets them to 0; either op ORs in 8 while a `DC` movie-end jump is recorded (`fieldscript.md` DC). The movie stops at its end frame, the field script continues at once (7F returns) and the field runs and draws behind the last movie frame, which stays on top:
- **flag 8 clear: hold.** The last frame stays opaque for 10 frames (the end frame and 9 more), then disappears in one cut.
- **flag 8 set: fade.** The last frame is drawn at alpha `(160 - n) / 160` in the n-th frame after the end frame (n = 0..159, about 2.7 s), then disappears.

Measured in RDE (frame series with the movie state, mean luma of each captured frame): crn_b16i `D4 #6,#8` (`b22fujyo`) fades over 160 frames at 60 Hz; under it the field of crn_b16i is already running its own fade-in from black (the field's luma behind the frame rises from about 7 at n = 56 to 21 at n = 108) and the following dialogue opens as the fade ends. opn_a05i `7E #3` (`a03kidfb`, whose last frame is white) is held opaque for 10 frames while the script's map jump loads the next room behind it, then cuts to that room's black entry. The title room's cold-boot `D4 #0,#520` (`a01op`) fades like crn_b16i.

OpenCross: `FieldWorld::play_movie` sets `MovieRequest::fade` from the op's flags (`D4`'s second operand, 0 for `7E`) and a recorded movie jump; the New Game movie (`FlowMachine`, the title's `D4 #2,#520`) passes 0x208. `App::end_movie` keeps the last decoded frame (`movie::Player::close(true, fade)`, `held()`); `draw_held()` draws it over the finished frame and `step_held(dt)` runs `movie::held_frame_alpha` (10-frame hold or 160-frame fade, 60 frames a second; a longer frame, e.g. a room load, counts as one) from the frame the movie ended in. A `DC` jump recorded before the movie is taken in `FieldWorld::movie_finished`: PREVIOUS_MAP_ID = the room register, the register = the target, and the room switches with no fade-out, so the held frame fades over the new room's entry. This applies to every FMV (title opening, 7E / D4 from scripts, skipped or finished). Routes: `title_fade`, `movie_jump`, `movie_opn`.

## 7. The title script (`opening.bin`) and the New Game movie
The second operand of every `D4` here is `#520` (0x208), the wipe / flag word; the first is the table row.
- UPDATE script (runs on entering the room): `OPFE1D #20,#0` (music fade, 20 frames), `WAIT 20`, `PLAY_SONG #255` (stop), then by `$ROOM_PARAM`: 0 -> `D4 #1` (row 1 `title`) unless var 0x42 == 1 (disc 2) where `D4 #0` plays; param 1 -> `D4 #1` only when var 0x42 != 0; param 2 / 3 -> the same `D4 #1` / `D4 #0` pair after `SET_0 $3E`. Row 1 `title` is the title loop / logo FMV played when the title room is re-entered (after game over / reset); row 0 (`a01op`) is the cold-boot opening.
- After the logo scene: `OPFE1D #20,#0`, `FADE 1,#32`, `WAIT 32`, layers 0 / 1 off, `PLAY_SONG #255`, `WAIT_SONG`, then the menu / name entry (`OPEN_MENU`, `RENAME_CHARACTER #0`, `OPEN_MENU`, `WAIT 24` each).
- **New Game tail**: `ADD_TO_PARTY #0`, `#1`, `RAND_MOD $4,#14` -> `ARRAY8_GET 0x310` -> `ADD_TO_PARTY` (third member), each followed by `COMMIT_PARTY_MODEL`; `MAP_JUMP_DC #22,#0` (records the jump; it is taken when the movie ends); then `D4 #2,#520` (`a02koryu`, skippable) + `WAIT_MOVIE` + `STOP_EXEC`. The fly-in to Fort Dragonia plays over the title room with no further fade or music op (music was already stopped), and `opn_a01i` loads when it ends.
- OpenCross: `FlowMachine::on_name` returns `FlowAction{movie_row = 2, load_room}`; `App::apply_flow_action` requests the row (`FieldWorld::play_movie(2, 0x208)`), starts it at once and keeps the room load (`deferred_flow`) until the movie ends or is skipped (a missing file loads the room immediately). The load is the DC jump: PREVIOUS_MAP_ID = the title room's register 8 (left by its FE 2F), so `opn_a01i` starts with variable 0x08 = 8, as the New Game+ start from the ending room does. Routes `newgame`, `ngplus_title`.

## 8. Skipping and pausing an FMV
RDE skips a movie whose flags have bit 0x200 (the `D4 ... #520` movies: the title room's and opa_a04f / opa_b04f row 8) on the press of any pad button: the d-pad, Circle, Cross, Triangle, Square, L1, R1, L2, R2, L3, R3, Select and Start all end the cold-boot `D4 #0,#520` (the movie flag drops about 0.9 s after the press); Start does not pause it. A movie without 0x200 (every other `D4`, which carry `#8`, and every `7E`, whose flags are 0) ignores the buttons and plays to the end (crn_b16i `D4 #6,#8` ran its full 51 s under 17 Circle presses).

OpenCross lets every movie be skipped (`architecture.md` section 13). The skip keys (`movie_skip_edge`, `src/app/app_sim.cpp`) are the PS1 buttons OpenCross does not use for anything else over a movie: the Up / Down / Left / Right, Ok, Cancel, Item, Menu, SelectLeft and SelectRight keys of both keyboard sets, K (Select), and the pad's d-pad, face buttons, shoulders and Back. Start / Space opens the pause screen instead (below); the speed keys (F1 / F2, the pad triggers = L2 / R2), the stick clicks (L3 / R3, hotkeys), Esc and keys outside the sets do not skip.

The PS1 and RDE have no pause during a movie, so the pause is an OpenCross feature:
- Start / P while a movie plays opens the RDE pause screen over the held frame (`App::pause_modal`, `src/app/app_sim.cpp`): `movie::Player::set_paused(true)` makes `update()` do nothing (the wall clock stops, no frame is picked, the on-screen frame stays and `draw()` shows it through the CRT ramp filter), and `Mixer::hold(true)` stops the movie PCM ring and its clock (`movie_frames_played`, the audio clock the player follows) and silences the music and voice buses. The decoder thread fills its ready queue and waits. Resuming (Start / P / B / X) continues frame and sound exactly where they stopped.
- Skip while paused is not possible: the pause screen is modal and swallows every button. Resume first, then skip. Esc still opens the settings window, which pauses the host as before.
