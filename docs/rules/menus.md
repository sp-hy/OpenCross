# Menu rules

Behaviour of the menus, shops, name entry, save and load screens, party editors and the pause screen: the rules, filters, formulas and limits the code enforces. Screen inventory and the flow machine: `architecture.md` section 7. Menu tables, the sell price and the forge fee: `formats/battle_data.md` sections 5.1, 11.3, 11.4. Save container, slot choice, New Game+: `formats/save.md`. Fonts, window skins, UI art: `formats/text.md`. Field script variables: `formats/fieldscript.md` section 10.8. Player walk / run and analog movement: `rules/field_actors.md` section 2. None of that is repeated here.

Code: `src/ui/menu/` (main menu, `GameState`), `src/ui/shop/`, `src/ui/title/`, `src/ui/party_screen.*`, `src/ui/pause_screen.*`, `src/game/game_flow.*`, `src/game/party_editor.h`, `src/app/app_sim.cpp`.

Conventions. "sfx N" is the menu sound id the code plays (1 cursor, 5 saved or sold, 6 cancel, 8 confirm, 0xC grid row change, 0x17 grid change, 0x18 refused, 0x1B traded, 0x48 equipment change, 0xBF forged or broken down). A refusal is only sfx 0x18 unless a message is named. Item stacks hold at most 99 (a further add succeeds silently without raising the count); the element stock has 192 slots, the gear and material stock 384. `party()` is the menu party: up to 3 valid ids in slot order, with a roster stand-in (section 1) replacing slot 0. Offsets such as "+0x12" are record byte offsets from `formats/battle_data.md`.

## 1. Main menu graph and input

Source: `main_menu.cpp`, `main_menu_main.cpp`.

Screens: Main (list, member pick, roster), Status, ElementChoice (Use / Allocate), ElementUse, ElementGrid, Equip, KeyItems, Settings, Save (Save / Load).

| List row | Opens | Exit cursor on return |
|---|---|---|
| 0 Status | member pick, then Status | 0 |
| 1 Elements | ElementChoice | 1 (from the grid: the Allocate pick) |
| 2 Equip. | member pick, then Equip | 2, on the member pick |
| 3 Items | KeyItems | 3 |
| 4 Customize | Settings | 4 |
| 5 Save/Load | Save (Load is always available; Save is gated inside, section 10) | 5 |

* **List.** Up / Down wrap over 6 rows (sfx 1). OK opens (sfx 8). Cancel closes the menu (the other exit is a Load, section 10): it stores the row in the cursor memory and sets closed (sfx 6).
* **Cursor memory.** On `open()` the list starts on the remembered row when options bit 0x01 is set, else on row 0. The remembered row is written only by Cancel on the list; the exit cursors above are not stored.
* **ElementChoice.** Two rows, Use and Allocate; Up / Down toggle (wrap); Left / Right do nothing. Use opens ElementUse. Allocate returns to the member pick with the target set to ElementGrid; during that pick the Use / Allocate list (and its needle) stays on screen instead of the main list. Cancel returns to the list on row 1.
* **Ailment marks.** Each party card on the main list shows a mark beside it for each of the record status bits 0x01, 0x10, 0x20, 0x08: menu sheet frames 0xAF, 0xB1, 0xB0, 0xAE at the card's position (bits in that order). HD art draws them from `hd/menu/menutim/menutim_41.png`, the 4x redraw of the strip the four frames are cut from.
* **Member pick.** Shows the party (at most 3 portraits). The pick cursor starts on the current member clamped to the party size. Left steps back and Right forward, wrapping; Up / Down do nothing. Left on the first member opens the roster instead of wrapping. OK opens the target screen with that member; Cancel returns to the list, from the Allocate pick to the Use / Allocate list on Allocate. Leaving Equip or the grid returns to the pick with the cursor on the member the screen showed last (`land_on_main`); leaving Status returns to the list.
* **Roster.** Lists all 44 characters (`save::kNumChars`), 17 rows visible (kRosterRows), scrolling one row at a time without wrap. It slides in and out over 20 ticks (kRosterSlide); input waits while it slides. Only available characters (recruited and not in the exclusion bitmap) show a row. OK on an unavailable row is refused (the confirm sfx 8 is requested first, then 0x18); OK on an available one opens the target screen with that character standing in for party slot 0 (`stand_in`). Right or Cancel slides it out and puts the pick cursor on member 0. On the Elements-grid and Equip picks, Triangle on an available row asks "proceed?" (Left / Right; the cursor is on Yes when the menu opens and keeps its last position afterwards): Yes empties the removable cells of that character's grid (sfx 0x17) or unequips all three accessories (sfx 0x48); No leaves it unchanged. Leaving a screen that was opened from the roster returns to the roster on the same row, not to the list.
* **Member switch.** L1 / R1 cycle through `party()` (wrap, sfx 1) on Status, Equip and the Elements grid. All three ignore L1 / R1 while a roster stand-in is active.
* **Input lockouts.** The first 4 ticks after `open()` ignore all input. Directions repeat after 350 ms every 70 ms (`DirectionRepeat`); a stick counts as a direction past 0.6, L2 / R2 past 0.5 of travel. The grid and the roster have their own locks (section 5). A message (`say`) clears after 150 updates; the saving screen holds input for 22 (section 10).
* **Screen transitions** (`MainMenu::Impl::Transition`, counts in 60 Hz ticks). The menu takes no input during one.
  * *Open*: every screen opened from the list or the Use / Allocate list (not ElementChoice itself, which switches at once). The screen fades linearly to black over 30 ticks (kOpenFade). One tick after the fade starts the member cards move right at 8.5 PS1 px per tick; on the way to Status, Equip or the grid the other portraits drop 16 rows per tick and the chosen one moves linearly to the first slot (x 16), arriving with the end of the fade. Items, Customize, Save/Load and Use move the cards only.
  * *Back*: a screen left for the list or the member pick fades linearly to black over 8 ticks (kBackFade) and stays black; there is no reverse motion.
  * Both last 32 ticks (kTransitionTicks); tick 33 cuts to the new screen at full brightness, with no fade-in.
* **Entering a screen** resets its cursors: Status shows the profile; ElementUse list and target at 0; the grid screen `grid_reset`; Equip slot 0 on the slot column; KeyItems 0; Settings row 0 with the skin picker closed; Save starts on Load when saving is blocked, else on Save.
* **What closes the menu.** Cancel on the list; a Load (section 10). After Cancel the host fades the field in over 0x10 ticks and a menu opened by a script sets script variable 0x4C = 1 when a file was written since `open()`, else 0; a Load does neither.
* **Opening.** The Menu key (pad North) opens it when the field is idle, no menu or battle is active, no message window is open (a frameless label counts) and global flag bit 12 (menu key disallowed) is clear. The field fades to black over 10 frames, the screen stays black for 40 more frames, then the menu cuts in at full brightness (`GameFlow::begin_menu_open_fade`; the game stands still meanwhile). A script MainMenu request opens it without the fade. A script Save request (field op FE 85, the ending's save prompt; save points open the main menu) opens the save-list-only mode of section 10, always with saving allowed.

## 2. Settings screen and the options word

Source: `main_menu_settings.cpp`; options word and defaults: `game_state.h` (`opt::`), `game/new_game.h`.

The options word is the u16 at head bytes 0x5A0..0x5A1 (`formats/save.md` section 4). Up / Down wrap over 8 rows and land on every row (sfx 1). Left and Right both flip the row's bit (sfx 1), so a second press undoes the first. OK only opens the skin picker (Window Frame while Custom) or the assignment page (Controller while Custom), with sfx 8; on any other row, or with Default chosen, it does nothing. Cancel returns to the list on row 4.

| Row | Bit | Clear / set | Effect in code |
|---|---|---|---|
| Sound | 0x04 | Stereo / Monaural | `Mixer::set_mono` every frame |
| Window Frame | 0x08 | Default / Custom | dialogue and key-item list use the skin byte only when set, else skin 0 |
| Cursor Position | 0x01 | Default / Memorized | main list start row, battle command cursor, results cursor |
| Accuracy Selection | 0x02 | Manual / Auto | battle menu option |
| Controller | 0x100 | Default / Custom | Custom applies the button assignment (below); OK on Custom opens the assignment page |
| [button] Pressed | 0x200 | Run / Walk | inverts the run button (`rules/field_actors.md` section 2.2) |
| Vibration Function | 0x400 | Off / On | rumble enable; also set by the title page and the pause screen |
| Left Stick Sensitivity | 0x800 | Digital / Analog | Analog makes a full stick tilt run (`rules/field_actors.md` section 2.2) |

* **Pad rows.** Vibration Function and Left Stick Sensitivity behave like the other rows whether a pad is connected or not: the cursor lands on them, they are drawn in the normal colours with the chosen-choice highlight, and Left / Right flip their bits. RDE's input layer reports a pad with motors and an analog stick to the game also under keyboard input, so its rows are never skipped or dimmed. (The original skips the Vibration row without a pad that reports motors and the stick row without an analog pad, and draws them dimmed with no highlight.)
* **Skin picker.** OK on Window Frame while it is Custom opens the picker instead of toggling. Left / Right step the skin byte 0..14 (wrap) to the next skin whose bit is set in the owned-frames mask (`slot.frames & 0x7FFF`); an empty mask makes the step a no-op. Only OK closes the picker (sfx 8); Cancel does nothing while it is open. The skin byte lives on `GameState::skin` and is set by the script (FE 1B, clamped 0..14). The slot carries it as variable 0x44 (head 0x1CC): leaving Customize sets the skin byte to 0 when Window Frame is Default and then writes it to variable 0x44 in the state (so a save made later in the same menu visit holds it), closing the menu writes variable 0x44 = skin byte into the field script variables, and every load (Continue or the menu's Load) reads the skin byte back from variable 0x44 (clamped 0..14; 0 when Window Frame is Default). New Game+ keeps no frame: the game starts with Window Frame Default (the options word of `formats/save.md` section 14.1), skin byte 0 and variable 0x44 = 0, as in the original, whose New Game+ list resets the options word when it opens, like the title list; only the owned-frames mask carries over (`formats/save.md` section 14). RDE capture (Continue on a cleared save with variable 0x44 = 5): with the list up the skin byte, variable 0x44 and the options word read 0 / 0 / 2, and after New Game+ (variable 0x7E = 2, MAP_ID 0) still 0 / 0 / 2.
* **Controller assignment.** The pair of words in `slot.button_cfg` (`formats/save.md` section 6: face word + analog word; the field pair serves the field, the menus and the world map, the battle pair serves battles) says which physical button triggers each function. While Controller is Custom, `platform::PadRemap` rewrites every frame's input in the app before anything reads it: function f (confirm, cancel, key items, menu, L1, R1, L2, R2: the keyboard keys, the pad buttons and the LT / RT axes of that action) takes the state of the button in its nibble, so the two buttons of an assignment trade places. Analog word: the left and right sticks swap their axes when nibble 0 is 1, the stick clicks swap when nibble 2 is not 2. Default leaves the input untouched and keeps the words; the page itself is read without the assignment. The glyphs of confirm, cancel, key items and menu (the main-menu legend, the Pressed row, `{key(0..3)}` in messages, the battle camera hint) show the button now on the function; the L1 / R1 page glyphs, the d-pad and Start glyphs are fixed.
* **Assignment page.** OK on Controller while it is Custom (sfx 8) opens the page of the field pair; Left / Right (any time) switch to the battle page and back. Layout (PS1 px): header frame 0x43 at (0x20, 0x18) with the page title and the two animated side pointers; frame 0x41 at (0x20, 0x50) with eight rows 24 apart (the glyph of the button on the function at x + 0x10, the function text at x + 0x54 with the disc glyphs, which carry a "button" word, x + 0x2D with the HD round glyphs; a row text may hold `{Button1}` / `{Button2}` / `{ButtonLeft}` / `{ButtonRight}` glyphs and a second text after it); frame 0x42 at (0x20, 0x132) with the two stick rows (the stick's name at x + 0x10, its function at x + 0x84; dimmed without a pad); frame 0x50 at (0x178, 0x132) with Start = Quit and Select = Default. Field page functions: Confirm/Talk, Run/Cancel (Walk/Cancel when [button] Pressed is Walk), Key Items, Menu, "(Same Function as Confirm)", "(Same Function as Cancel)", Low-Speed Mode, High-Speed Mode; sticks Walk/Select (Run/Select with Walk) and Change Direction on the Spot. Battle page: Confirm, Cancel, Choose Character to Control (= d-pad), Change Target Selection View, two more Choose Character rows, Low / High-Speed Mode; sticks Select and Unused. The cursor starts on row 0 and keeps its row when the page changes; rows 0..7 are the buttons, rows 8 and 9 the sticks (RDE keeps 10 rows with a pad and 8 without; the original's two click rows 10 and 11 are not offered). Up / Down wrap. A button pressed on a row 0..7 gives the row's function to that button and the function the button had to the row's old button (a swap of two nibbles); Circle on a stick row swaps the sticks. Select (sfx 1) puts the defaults of the shown page back, Start alone (sfx 8) leaves; Cancel does not leave. Every action but leaving plays sfx 1.
* **Defaults.** A new game or New Game+ starts from the word in `formats/save.md` section 14.1, then sets bit 0x400 from the title vibration page (section 13). A loaded slot keeps its word.

## 3. Status screen

Source: `main_menu_main.cpp`, `game_state.cpp`.

OK toggles the profile panel and the equipment panel; Cancel returns to the list on row 0; L1 / R1 change member and return to the profile with the model camera reset.

* **Card values.** Name; HP as current / maximum, each shown as `min(value, 999)`; the current HP uses the warning colour when `cur_hp < max_hp / 8` (integer division). STR, ACC, MAG, RES, AGI, M.RES are the record fields `atk, hit, mag, def, evd, mdef`, each `min(value, 99)`. The record holds the character's own value: neither equipment nor a growth lookup is applied on this screen (the equip screen, section 4, adds gear). INNATE shows the colour disc of `innate(character)`: the record colour bit for characters 0 and 43, else the `char` record's innate byte (the dream record set while the dream state is active).
* **Stamina recovery** (Status and Elements-use panels). `min(rate + sum over accessory slots 2..4 of gear.mag where gear flag 0x80 (stamina) is set, 99)`; `rate` is byte +0x1F of the character record.
* **Ailment badges.** Four badges for record status bits 0x01, 0x10, 0x20, 0x08.
* **Hurt pose.** The model opens on pose 3 instead of pose 0 when the member's record has a status of mask 0x39 or `cur_hp < max_hp / 8`; Square's pose cycle then runs 3, 1, 2 (index 0 stays the hurt pose). PS1 (Serge poisoned at 78 / 800 HP): the screen set pose 3 at its first frame and drew the poison badge, the warning-coloured HP and the green status bubble over the head; OpenCross draws the same.
* **Grid minimap.** One tile per unlocked grid cell.
* **Profile text.** Table row keyed by the character's body (section 14) when it is at most 0x31, else by the character id; at most 7 lines, trailing blank lines dropped. The 3D model is the menu model with the same key (body up to 0x32).
* **Pad camera.** Triangle toggles between the turning model and the pad camera; in pad mode Square steps the pose 0, 1, 2. The model logic ticks every second 60 Hz frame. Auto turn +8 per tick. Pad camera: Left / Right turn 16, Up / Down move 32 (distance clamped between the model's nearest distance and 0x960); with L2 held the directions pan by 8 (limit 0xAA); with R2 held Up / Down tilt by 16 (limit -0x200..0).
* **Model drawing rate.** The original (PS1 and RDE) draws the Status model once per model tick, so the turn, the pose, the body and the weapon all move at 30 Hz. OpenCross draws at the display rate: the pose is interpolated between its steps and the camera (turn, tilt, zoom, pan) between the camera of the previous tick and the current one by the same time drawn, so neither moves in 30 Hz steps while the other runs smoothly. The weapon hangs on the joint matrix of the same pose the body is drawn with in that frame.

## 4. Equip screen

Source: `main_menu_equip.cpp`; rules `GameState::equip_candidates`, `can_equip`, `equip`, `stats_with`. As on the PS1 the panel shows ATK, DEF, MAG and MDEF above 99 when the gear takes them there, HIT and EVD capped at 99, and base stats capped at 99. A "%" follows the HIT and EVD values on the current rows, and on the preview rows while the list is open (whether or not a preview is shown), in every language; the preview rows carry an arrow after each caption. With the HD panel art the arrows are part of the frame image and the "%" is a number-face glyph; with the disc art (`ps1_screen`) the arrows, the "%" and the divider between the preview and current rows are the sheet parts of the "wind" texture at their PS1 positions. The six stat captions are left-aligned at the x of the Japanese sheet caption (ATK and DEF 51, M. ATT. 47, M. DEF. 132, HIT and EVD 141; preview and current rows alike) plus the language offset (English -4 for ATK / DEF and -8 for HIT / EVD), so they end before the arrows.

Slots 0 weapon, 1 armour, 2..4 accessories. The slot column (Up / Down wrap over 5): OK opens the candidate list, Cancel returns to the member pick (list row 2, cursor on the member shown). Triangle does nothing here (removing all accessories is the roster's Triangle prompt, section 1). L1 / R1 change member, from the slot column or the list: the screen starts again on the weapon slot with the slot column focused and the list cursor and scroll at 0. The list: Up / Down without wrap over `max(entries, 11)` rows, 11 rows visible (kVisibleRows), Cancel back to the slot column. A short list leaves blank rows the cursor can still reach. The list cursor is not reset when the list opens: it starts at row 0 when the screen opens and is otherwise kept across slots and visits; while the slot column has the focus a cursor past the end of the current slot's list moves to the row just past the last entry (row = entry count, scrolled so that row is the last visible one).

* **Candidate filter.** A weapon or armour list holds, in bag stock order, every stack with quantity > 0 whose item kind (low nibble of the item-info category) equals the slot (0 weapon, 1 armour), then one reserved row. An accessory list opens with one reserved row, then every stack of kind 2 in bag order, then every stack with an id below 0x20 (the materials, taken without a kind test) in bag order. Reserved rows and the blank rows past the end are not drawn and show no description. On an accessory list OK on the reserved row or a blank row takes the accessory off when the slot is filled (sfx 0x48, the item goes back to the bag) and is refused (sfx 0x18) on an empty slot; on a weapon or armour list it is always refused.
* **Selectable.** A row is selectable when the equippable-by mask has the character's bit (ids below 64) and, for accessories, the conflict test passes: a candidate whose gear slot mask overlaps the accessory being replaced is never in conflict; otherwise `gear.slot_mask & (OR of the slot masks of the three worn accessories)` must be 0. No material has a character bit, so materials always list in grey. Other rows stay listed in grey; OK on one plays sfx 0x18. Quantity shows as `min(qty, 99)`, except item 0x40 (the second Einlanzer, a pair), whose row always shows 2; the stock count itself is not changed.
* **Preview.** For the highlighted selectable row the screen shows the new values in a raised or lowered colour next to the current ones. The reserved row and the blank rows preview with item 0 when they would take a filled accessory slot off, and show no preview otherwise.
* **Stat formulas** (`stats_with`; `ch` = record, `o` / `d` = sums over the equipped accessories with gear flag 0x20 (offence) / 0x40 (defence) of gear bytes +4 / +5 / +6, `wp` / `ar` = the weapon / armour gear records):

| Stat | Formula | Display cap |
|---|---|---|
| HP | `max_hp` | (not shown) |
| ATK | `ch.atk + o4 + wp[4]` | 999 |
| M.ATT (mag) | `ch.mag + o5 + wp[5]` | 999 |
| HIT% | `(2 * (ch.hit + o6 / 3)) / 3 + wp[6] / 3` | 99 |
| DEF | `ch.def + d4 + ar[4]` | 999 |
| M.DEF | `ch.mdef + d5 + ar[5]` | 999 |
| EVD% | `ch.evd + d6 + ar[6]` | 99 |

  All divisions are integer. A slot with no item contributes 0.
* **Equipping.** `equip` re-checks `can_equip` (including a bag count > 0 for the item), takes one copy from the bag, returns the replaced item to the bag, and writes the id into the character's weapon, armour or accessory word. A weapon change on Glenn (id 0x13) also sets his model byte (record +0x2D, low byte): 0x32 (`gren2`, two swords) when the new weapon is item 0x40 (the second Einlanzer), else 0x13 (`gren1`); and in every grid cell (id masked 0x3FFF, the 0x4000 bit kept) it swaps his sword techs: with item 0x40 elements 0xDA / 0xDB become 0x9A / 0x9B (the two-sword Sonic Sword / Dive & Drive), with any other weapon back. The battle loads the PC's model from that byte, so this is what decides one or two swords; Dash & Gash, which has no two-sword element, picks its two-sword clip by the same byte (anmseq op 0x67, `battle_effects.md`). The record stats are not rewritten; gear is added at display time. Success plays sfx 0x48 and closes the list. A replaced item at 99 held goes back without raising the count (it is lost, as in the original). If the bag has neither a stack of the replaced item nor a free slot, the change is refused (sfx 0x18) and nothing moves; with fewer than 256 item ids in 384 slots this cannot happen in play.

## 5. Elements screen (grid editor)

Source: `main_menu_elements.cpp`; rules `game_state.cpp` (`can_place`, `can_remove`, `swap`, `auto_fill`, `sort_elements`), `MenuRules`.

**Geometry.** 8 rows (the element level, row r holds level r + 1) by 10 columns. A character has a cell where its record level mask (+0x30, one u16 per row) has the bit; cells are stored compactly in row-major order, at most 48. A cell is usable only when its bit is set in the character's unlocked mask for that row. L1 / R1 re-enter the screen with the next member (`grid_reset`).

**List.** Two label rows (0 and 1) followed by every occupied stock slot (id nonzero, quantity > 0) in stock order, 192 rows at most (so 190 elements). Rows 0 / 1 read Remove All / Remove; Right on the list (ignored while a cell is picked) shows the second pair, Auto Allocate / Fill Blanks; Right again moves to the grid; Left from the second pair returns to the first; Left from the first pair moves to the grid. 11 rows visible, Up / Down without wrap, Triangle opens Reorder.

**Focus model.** Focus is the list (0) or the grid (1). One pick is held at a time:
* An element or Remove picked on the list waits for a cell (`pick_element`). The cursor goes to the grid on the element's level row clamped into the character's unlocked rows (first open row .. deepest open row; sfx 0xC when the row changes); if the member may not hold the element, or no unlocked row lies within its reach, the pick is not taken (sfx 1 only). Reach is the low nibble of record byte +0x12. Remove and the row past the end of the list hold no element: they go to the grid on the current row and accept any cell.
* A cell picked on the grid first waits for a list row (`pick_cell`). On the list, OK with Remove or an element applies it to that cell (the label rows Remove All, Auto Allocate and Fill Blanks are refused); Left takes the picked cell back to the grid as a swap source (`swapping`); Cancel drops the pick.
* Swap: OK on a second cell swaps the two (`swap`); Cancel drops the swap and stays on the grid.
* Grid keys: Up / Down move along the row to the next unlocked cell (wrap); Left / Right change to the next lower / higher row that has an unlocked cell, wrapping. Wrapping past the bottom or top row moves to the list instead, unless an element pick or a swap is pending. A row change plays sfx 0xC. While an element is held (list pick, swap source or picked cell), a move onto a row outside its placement window is ignored. Cancel on the grid drops a swap, or a list pick (back to the list), else returns to the list. Cancel on the list returns to the main list on row 1 (to the roster if a stand-in is active).
* Applying (`apply_to_cell`, sfx 0x17 first): Remove empties the cell (on an empty cell it changes nothing and still hands the focus back); an element replaces the occupant, which goes back to the stock. An element that fails the window, eligibility or stock check plays sfx 0x18 and keeps the pick; a fixed occupant never gets this far, OK on a fixed cell is refused on the grid. When the element came from the list the focus returns to the list, when the cell came first it returns to the grid.

**Placement legality** (`can_place`, first failing check wins): no such cell; cell locked; occupant fixed; the id has no element record or the character may not hold it; outside the placement window; no copy in stock (the cell's own occupant does not count); the occupant has neither a stack nor a free slot to go back to (Full; unreachable with fewer than 128 element ids in 192 slots).
* **Order.** Placing first takes the new copies, then returns the occupant. Refilling a stack cell with its own element therefore leaves in the cell what the stock held (at most 5) and returns the old count; replacing an element with itself at 99 in stock stays at 99. A return to a stack at 99 is accepted without raising the count.
* **May hold.** The element's menu eligibility bit for the character (ids 0..47, `menu_pg` bytes 0..5; ids past the table are open to all), and for innate-only elements (record byte +3 bit 0x80) the element colour must equal the character's innate colour exactly.
* **Fixed.** Id >= 0x80 (techs and special cells), or element record byte +1 bit 0x02. Fixed cells cannot be picked, swapped, replaced or removed. A tech held in the stock (the level 7 techs a character receives as an element) is placed like any element: its menu eligibility limits it to its owner and its level window to its row; once placed it is fixed by its record flag and stays.
* **Placement window.** The element of level L fits row r (0-based) when `L - hi <= r + 1 <= L + lo`, `hi` and `lo` being the high and low nibble of record byte +0x12.
* **Stacks.** An element whose record byte +0 has `(b & 0x30) == 0x10` is a consumable stack: placing takes up to 5 copies (kStackMax) from the bag, as many as exist, and stores the count in the cell; removing or replacing returns the stored count (a cell holding 0 returns none). Other elements use one copy.
* **Swap rules.** Both cells exist, are unlocked and are different; neither holds a fixed element; each element must satisfy the window of the other cell's row. An empty cell may take part. Counts travel with the ids. (Picking the same cell twice is treated as success, no change.)
* **Remove** (`can_remove`) fails on an empty cell, a fixed cell (checked before locked), a locked cell, and (Full) when the element has neither a stack nor a free slot in the stock.

**List dimming.** A listed element is dimmed when the character may not hold it; when a cell is picked and its row is outside the element's window (not while swapping); or when the element's reach (level row +- low nibble) misses every row between the first and deepest unlocked row of the character.

**Prompts** (question in the description panel; Cancel dismisses, sfx 6):
* Remove All: Yes / No (Left / Right), default No; Yes removes every element with 0 < id < 0x80 from unlocked cells of the member (fixed ones stay), sfx 0x17.
* Auto Allocate / Fill Blanks: choice "this member" (default) or "whole party" (Up / Down). The whole party is refused (sfx 0x18) while a stand-in is active. Auto Allocate clears the member(s) first, Fill Blanks only fills empty cells.
* Reorder (Triangle on the list): three orders, cursor starts on the first (Up / Down wrap); the stock is repacked from slot 0 with quantities kept.

**Reorder orders** (stable sort by group, then key):

| Order | Groups |
|---|---|
| Innate first | any id: group 0 if the element colour has the member's innate colour (key id); group 2 if it has the opposite colour (key stock slot); everything else group 1, ordered by the exchange sort below |
| Attack first | ids 1..0x30 group 0 by descending id; the rest group 1 by id |
| Heal first | 0x80 group 0; 0x55..0x6B group 1 by id; 0x31..0x54 group 2 by id; 1..0x30 group 3 by descending id; 0x6C..0x7D group 4 by descending id; rest group 5 by id |

The opposite colour pairs are bits 0x04 <-> 0x40, 0x08 <-> 0x10, 0x20 <-> 0x80; the member's innate colour is the innate bit masked with 0xFC (a member with no single innate bit has no opposite group).

Innate first, group 1: the 192 stock slots, with the group 0 and group 2 entries and the empty slots set to 0, go through an exchange sort: for each position i in turn, every later position j (from i) is swapped into i when its id is lower than the id at i or the id at i is 0. A 0 is lower than any id, so a later hole displaces an entry and is displaced again by the next entry; the ids come out ascending only where no hole lies between them. Group 1 takes the nonzero ids in the resulting order.

**Auto-allocate algorithm.**
1. Buckets: stock slots (first 190 occupied) with ids below 0x80, bucketed by element level (bucket = level - 1), in stock order.
2. Two passes, exact level first (`fallback` false), then fallback; each pass walks rows 7 down to 0, and each row for every member in party order (one member for "this member"), so members share the stock in that order.
3. For each empty unlocked cell, left to right: sort the row's bucket by score, descending (exchange sort, an entry moves forward only for a strictly higher score), then take the first stock slot that passes: id nonzero, member may hold it, element fits the cell row's window, stock quantity >= 1 (>= 5 for a stack), and fewer than 2 copies of it already placed on that member. The fallback pass also searches the buckets of rows +1, -1, +2, -2 ... around the cell row.
4. Score of an element: empty slot -200; two or more copies already placed -100; otherwise the `menu_pg` bonus for 0 copies (byte 0x0C) or 1 copy (byte 0x0D) placed, then -10 if the element colour intersects the opposite colour, else +10 if it intersects the member's innate colour (members whose innate colour has no single opposite get neither).

**Timing locks** (menu frames during which grid input is ignored): after opening, Remove All, Auto Allocate, Fill Blanks and Reorder 27 (kLockOpen); list to grid 18 (kLockToGrid); cancelled cell pick 9; list-side fill 17; grid-side fill 15; swap 10; column move 9; grid to list 4; row change 40 (kLockRow: a 30-frame slide, 15 PS1 px per frame out then in); a row change started from the list adds the 3-frame hand-over (kHandOver).

## 6. Use element from the menu

Source: `use_flow.cpp` (the state machine), `main_menu_elements.cpp` (the pad mapping and the drawing), `game_state.cpp` (`use_element`).

The screen has three states: the element list, the party target and a roster of all 44 characters.

* **List filter.** Stock slots with quantity > 0 and id > 0 whose `menu_pg` byte 0x0B has bit 0x80 (usable). Up / Down without wrap, 11 rows visible; every press sounds (sfx 1) even at an end. The cursor may rest on a blank row (the 11 rows are always there: the last row reachable is `max(count, 11) - 1`); OK on a blank row does nothing. Cancel returns to the main list on row 1.
* **Opening the target.** OK on a listed row (sfx 1; the main list's confirm is 8) shows the list state for 2 ticks, then the party target. The target cursor is reset only when the screen is entered, not at every pick, so it keeps its member across list visits.
* **Party target.** Over `party()` (at most 3). Up / Down clamp at both ends (no wrap; every press still sounds, sfx 1). Left opens the roster, Cancel returns to the list (sfx 6).
* **Roster.** Rows for the 44 characters, 12 visible at 20 px (panel at PS1 (8, 167), 232 x 248), top row 0..32. Up / Down clamp at the ends of the whole list and scroll one row at the panel edge. The cursor's character (top row + row, available or not) stands in for party slot 0 while the roster is up: the top card (47, 27) shows its status panel, or the empty card frame when it is not available, and the portraits stay dim. Only available characters (recruited and not excluded, section 1) show a row: name, HP label, current / max HP. The cursor sits left of the panel, a pointer bounces on its right edge (Right), scroll arrows at (237, 394) / (237, 185). Right returns to the party target (sfx 1), Cancel too (sfx 6); both restore slot 0. The roster cursor starts at the top at every Left.
* **Refusal.** OK on a target the element cannot act on (not available; Heal on full HP; Cure with none of its statuses) plays sfx 0x18 and changes nothing: the state, cursors and stock stay.
* **Heal** (`formats/battle_data.md` 5.1): heals the listed amount, capped at max HP. Refused when `cur_hp >= max_hp`. Heal size 3 heals 0 and still consumes a copy. A character at 0 HP is healed like any other.
* **Cure:** the element record's status mask (+0x18, 32 bits) is tested against the record's status word; refused when `(status & mask) == 0`, else the mask's bits are cleared. The save keeps the low byte of the word, and the usable cures have bits above 7 (Antidote 0xB01, Ointment 0xB00008, Brace 0x0B000010, Medicine 0xB0000020, Panacea 0xFFFFFF3F) that no saved state or script sets, so the engine tests and clears the low byte only; the results are the same for every reachable state.
* **Result.** On success one copy is consumed. A heal rings sfx 0x12 with sfx 0x13 layered on its own sound mask (0x80), a cure rings sfx 0xBE; the confirm sound 8 is not used. PS1 (an Antidote on a poisoned Serge from the field menu): the presses rang 8 (Elements), 8 (Use), 1 (the list row), 0xBE (the target), and the record's status byte went from 0x01 to 0; OpenCross the same, with one copy taken from the stock. With copies left, the list state shows for 5 ticks and the same target (party member or roster character) comes back with its cursor; the roster character keeps standing in meanwhile. When the last copy goes, the screen returns to the list, whose cursor and scroll are kept (a cursor past the shortened list rests on a blank row), and slot 0 is restored.
* **Highlight.** The list row drawn in the highlight colour is the one on the screen row equal to the active state's cursor: the list cursor in the list state, the party cursor in the target state, the roster cursor in the roster state (the description and the list arrow stay on the list cursor).

* **Menu list** (Items row). The owned ids in ascending order (ids 1..64 from the 64-bit key-item bitmap), 15 rows visible, Up / Down without wrap, Cancel returns to the main list on row 3. It is read-only: it shows the picture `menu/keyitem/NN` and the three description rows of the key-item table; nothing can be used here.

## 8. Shops

Source: `shop_logic.cpp` (rules), `shop_screen.cpp` (flow).

Script requests: ElementShop opens the element shop, TradingPost the trading post, WeaponShop the blacksmith (forge, break down, sell); the Smith Spirit key item opens the blacksmith too. The argument is the shop row id. Sounds: 1 cursor, 8 confirm, 6 cancel, 0x18 denied, 5 bought or sold, 0xBF forged or broken down, 0x1B traded. Gold gains from selling and breaking down are clamped to 9999999 (kMaxGold) without a refusal.

**Opening and closing.** A shop request (script op or the Smith Spirit) opens as the main menu does (section 1, *Opening*): the field fades to black over 10 frames, the screen stays black for 40 more, then the shop fades in from black over 0x10 ticks; the game stands still until the fade-in starts. The original has no fade-in (the PS1 cuts to black and shows the shop a few frames later; RDE fades out and holds as described, then cuts the shop in); OpenCross adds one. Closing the shop hands the field back faded in from black over 0x10 ticks.

**Flow.** Top list (Element: Buy, Sell; Smith: Forge, Break down, Sell; Up / Down wrap; Cancel closes the shop). Smith goes through a category list (weapon, armour, accessory = item kind 0, 1, 2). Then the item list (wrap, 11 rows visible, Cancel one level up), then quantity (Buy, Sell element, Sell gear) or a Yes / No confirm (Forge, Break down; default No). An empty list on entering is refused (sfx 0x18). Quantity: Right / Left +-1, Up / Down +-10, clamped to 1..max without wrap; OK commits at once (no confirm). After a change the list is rebuilt and the flow falls back one level when the list is empty.

**Element shop** (price: `formats/battle_data.md` 5.1, clamped >= 0):
* Buy list: the shop row (`el_shop`, ids up to the first 0). The Cheats option "every element in shops" appends every other sellable element with price > 0, by id.
* Buy max = `min(99 - owned, gold / price)`. OK on a row is refused if the price exceeds gold or the max is below 1. Buying checks owned + qty <= 99 (Full), `price * qty <= gold` (NoGold) and a free stock slot (else rolled back, Full). Cost = `price * qty`. A price of 0 cannot be bought.
* Sellable: the `menu_pg` no-shop flag clear (5.1), id > 0, not fixed. Sell list: bag elements in slot order, then elements that are only placed in an available character's grid.
* Sell max = the bag copies. The info panel's Allocated row counts the copies placed in the available characters' unlocked cells (a stack cell counts its copies); its Stock row shows the bag count minus the quantity chosen. Raising the quantity past the bag count (or opening it on an element the bag does not hold) while any placed copy exists opens the *grid picker* with the quantity clamped to the bag count; with none placed the quantity just stops at the bag count. Proceeds are `(price * total) >> 2`, computed on the total of bag and picked copies, not per unit.
* **Grid picker.** A panel (shop units (20, 16), 272 x 368) over the shop; for the first 30 ticks the prompt reads "the rest of the Elements are allocated to the members listed on the left" and input waits (Cancel works), then the prompt asks whose grid to take from and the Confirm box (200, 392) with its cursor appears. The 44 characters sit in two columns of 22 (x 0x28 / 0xA8, 16 units apart from y 0x1C), a row only for available characters: name, and for a character that still has copies the name in orange with "x n". Up / Down move one character; Up from the first row of a column and Down from the last row go to the Confirm cell (the cursor index 21 / 22 and below 0 / past 43 are the Confirm cell); from Confirm Up goes to the last character, Down to the first. Left / Right switch columns. OK (auto-repeat) takes one copy from the character under the cursor when it is available and has one left; the quantity shown is the bag quantity plus the picks, the total price follows. OK on Confirm sells, Cancel at any point returns to the list and sells nothing. After any element sale (quantity or picker) the list cursor and scroll return to the first row. The sale removes the picked copies from each character's unlocked cells, first cells first (a stack cell is reduced by the rest, and its id cleared at 0 copies), and the bag quantity from the stock; nothing goes back to the bag.

**Blacksmith.**
* Forge list: the shop's `waa_shop` row filtered to the category; the Cheats option widens it to every craftable, non-dummy (price > 0) piece of that category.
* Recipe: the nonzero counts for materials 1..31 in the forge table (the original walks materials 0..31; material 0's count is 0 in every shipped row, and the recipes use materials 1..22). Forge needs every count in the bag (else "short of materials", one message per category) and gold >= cost (else "not enough gold"); no recipe is silent. Cost: `formats/battle_data.md` 11.3. There is no check of the count held: it takes the materials, adds the piece, then deducts gold, so at 99 held the materials and gold are spent and the count stays 99. If the bag has neither a stack of the piece nor a free slot the forge is refused (Full, sfx 0x18) before anything is taken; with fewer than 256 item ids in 384 slots this cannot happen in play. The Cheats option "no crafting cost" skips the material and gold checks and takes nothing.
* Break down and sell lists are built the same way: first the bag's pieces of the category in stock order, without item-info bit 0x20 (break down) or 0x80 (sell); then, for every available character (recruited and not excluded) in id order, the worn pieces of the category's slots (weapon; armour; the three accessory slots) without bit 0x20 that are not listed yet. The worn pass tests 0x20 in both modes, never 0x80; since every piece of the game with bit 0x80 also carries 0x20, no unsellable piece reaches the sell list that way. The break down list also drops pieces without a recipe (only unused dummy ids).
* **Smith refusals.** OK on a row that cannot proceed shows a message for 60 ticks during which the shop takes no input, then the list prompt returns: forge short of materials (one message per category) or of gold, and break down of a worn-only piece ("I can't disassemble what you still have equipped."), each after the confirm sound 8; the sale of a worn-only piece ("I can't buy what you still have equipped!") with sfx 0x18.
* Break down: refused (message) when only worn copies exist (bag count 0). It removes one bag copy and returns each recipe material one unit at a time; a unit that no longer fits (the material at 99 or no free slot) is paid as gold (11.3), summed per material as `price * over / 4` in integer arithmetic and shown in a second message line when the total is above 0.
* Sell: max = bag count (worn copies are never sold; a worn-only piece is refused, see above). Proceeds = `(price * qty) >> 2` on the total (11.4), so three pieces at price 10 pay 7, not 3 x 2; the list row shows the price of one piece (`price >> 2`) and the quantity window the total. Materials (kind 4) are refused.

**Trading post** (own three-stage loop over the shop's `trade` row; `battle_data.md` section 8 for the row layout).
* Stage 0: greeting; OK enters the goods list, Cancel closes.
* Stage 1: the goods list: the row's entries up to the first goods id 0; an entry with level sum 0 is a hole (no goods, not counted). Up clamps at 0, Down at count - 1, no wrap. Names are prepared one row per frame and input waits until the list is ready. OK enters the offer, Cancel returns to the greeting.
* Offer list: every element stock slot with a nonzero id and without the `menu_pg` no-shop flag (192 rows at most, at least 11 rows), cursor row 0..10, scrolling by one; Down never moves onto an empty row. Rows the entry's colour mask refuses are dimmed. Cancel returns to the goods list (sfx 6) and the offer is cleared on the next visit.
* A press of OK (auto-repeating while held; sfx 8 on every press and repeat) adds one copy of the row's element to the offer when the entry's colour mask is 0 or shares a bit with the element's colour, the offered level sum is still below the entry's level sum, and the offered count differs from the stock count of that element. Level sum = the sum of element level * offered copies.
* When the sum reaches the required level sum the "Make the exchange?" question opens (default Yes; Up / Down toggle). OK is accepted only more than 30 frames after the question opened. Yes takes every offered copy from the stock and adds one unit of the goods item (sfx 0x1B); No (sfx 8) and Cancel (sfx 6) discard the offer. A single copy may overshoot the required sum. The offer list is not rebuilt after a trade.
* The goods are added with the normal stack add: at 99 held the elements are still taken and the goods are lost. With neither a stack of the goods nor a free slot (unreachable in play) Yes is refused with sfx 0x18 and nothing is taken.
* The goods cursor indexes the row's entries, holes included, while Down clamps at the count of entries without holes: a hole in the middle would make the last entries unreachable and let the cursor rest on a hole (goods 0). No row of the game's `trade` table has a hole before its end.
* **Layout check (JP, goods list, 512 x 432 shop units).** Against the PS1 screen the list panel (20..251 x, bottom 357..359), its header rule (y 64..65), the info panel (315..497 x, y 70..195), the "in stock" row, the colour box, the cursor arrow and the clock / gold block agree within 1 unit; the list panel's top rule sits 2 units lower than the PS1's (RDE shape art). The item description (style 0x8F) starts 9 units higher than the PS1's (y 85 against 94); that offset is RDE's per-language baseline of the style: RDE's Japanese layout puts the description's first line within 1 canvas pixel of ours.

## 9. Name entry

Source: `ui/title/name_entry.cpp`, `name_codec.cpp`.

* **Opening.** A script name entry (field op FE 4A, `MenuKind::NameEntry`) opens as the main menu does (section 1, *Opening*): the field fades to black over 10 frames, the screen stays black for 40 more, then the name entry (or the user guide before it) cuts in at full brightness, with no fade-in; the game stands still meanwhile. The title's New Game name entry follows the title's own fades (section 13).
* **Keyboard.** Non-JP languages: a 10 x 14 Latin grid (upper and lower case, accented letters, `ß`, `#`, digits, `+-*@<>()[]:;,.!?` and inverted marks); a blank cell inserts a space. JP: three 10 x 10 pages (katakana, hiragana, alphanumeric) selected by buttons; blank is U+3000. Nothing else can be typed (no text input from the keyboard).
* **Length.** `max_name_length`: 12 on the Latin keyboard; 6 in JP, 4 for Viper (character id 5). The buffer is always that many cells, blank padded.
* **Navigation.** Both layouts open on the button column: the Latin layout on Change Name, the JP layout on the active page's tab. The button column takes only Up / Down (wrap); Left / Right do nothing there. OK on Change Name or a page tab enters the grid on the cell it was last left from ((0, 0) the first time). Up / Down / Left / Right move without wrap inside the grid; a press past any edge goes back to the button column, on the button that was focused. L1 / R1 move the text cursor.
* **Entering.** OK in the grid writes the cell at the cursor and advances unless on the last cell (which is overwritten repeatedly). Cancel is Backspace: it blanks the cell at the cursor, then moves left; it works in the grid and while a page tab or Change Name is focused, and does nothing on Confirm or Default. There is no way to leave the screen without a valid name, and only OK on Confirm accepts it: Start (pad Start, Space) does nothing on this screen, in the grid or on a button.
* **Buttons.** Latin: Change Name (back to the grid), Confirm, Default. JP: the three page buttons, Confirm, Default. Default restores the text the screen opened with: the character's custom name when there is one, else the language's name (system-message table), padded to the length.
* **Rejection.** Trailing U+0020 and U+3000 are trimmed. The name is rejected, with a 0.45 s flash and sfx 0x18 and the screen stays, when it is empty or equals クロノ, くろの, "chrono" or "crono" (Latin letters case-insensitive). The reserved list applies to every character. Only trailing blanks are trimmed: leading blanks stay and count as part of the name.
* **Initial text.** The custom name of the character if there is one, else the language's name.
* **Storage.** A confirmed name equal to the language's name of the character (after the trim) erases the custom name instead of storing it, at New Game and on a script rename alike: the character then follows a language switch, `ext_save.dat` holds no name for it, its save record goes back to the default, and field op FE 7E can give Mojo his new name (`formats/fieldscript.md`). Any other name is kept whole (UTF-32 in the flow's custom names, saved to `ext_save.dat` / the page file). The save record gets only what the game font can encode, at most 6 symbols (`pack_record`); characters the font lacks are skipped, and a name with nothing to encode leaves the default record. On load, an `ext_save.dat` name replaces the record's when the languages match. A name counts as unset when empty, all blanks, containing an undecodable code, or (outside JP) containing a code point at or above U+3000; a record still equal to the character's default record names nobody either.

## 10. Save and load screens

Source: `main_menu_save.cpp`; title side `ui/title/slot_list.*`.

**In-game flow** (`save_phase`):

| Phase | Screen |
|---|---|
| 0 | Save / Load choice. Up / Down toggle only when saving is allowed; OK on Save when blocked is refused. Cancel returns to the main list on row 5. |
| 2 | Target choice: OpenCross, Slot 1, Slot 2 (Up / Down wrap). Starts on OpenCross when the page holds a file, else on Slot 1. Cancel returns to phase 0 (save-list-only mode: closes the menu). |
| 3 | "No save data" (Load on an empty target); confirm or 120 frames returns to phase 0. |
| 1 | The file grid or list. Cancel returns to phase 0 (save-list-only mode: to phase 2). |
| 4 | Saving: the file is written at the confirm; the grid or list stays (a card grid keeps the boxes it showed before the write, with the overlay of the bullet "Saving overlay" below; it is read again when the saving screen ends), the detail panel goes, and the progress frame (caption "Progress", its bar empty), the line "Saving to Slot n..." in the description frame and an empty message frame show. Input is ignored. 22 frames after the confirm the save chimes play and the screen returns to phase 0 with the Save / Load cursor where it was (save-list-only mode: to phase 2 with the target kept). No result message follows. |

* **List brightness.** The Save / Load list, its leader lines, the dial and the needle draw at full brightness only in phase 0; in every other phase they draw at half (RDE capture: the Load label's brightest pixels 188 -> 94, the needle's 145 -> 75 between the Save / Load choice and the grid or the saving screen). `MainMenu::Impl::save_dial`.
* **Save-list-only mode** (`MainMenu::open_save_list`, the script Save request). The menu opens on the Save screen in phase 2 in Save mode; the Save / Load list, its dial and the description frame are not drawn and there is no phase 0. Everything else (targets, grid, page, overwrite confirm, `saved`) is as in the normal flow.
* **Save allowed.** The menu opens with saving allowed when script variable 0x3C == 1, and always in the save-list-only mode. Having used the debug tools only shows a warning line (a toast for the script request); it never blocks a save.
* **Card grid.** 15 boxes (8 + 7), one per file in the card's directory order (not by file number); each box shows its file's number, whatever that number is (the game itself only writes 00..14). Left / Right step with wrap (Save on card 1 wraps within boxes 1..14); Up / Down jump 8 boxes (boxes 7 and 8 stay). Box 0 of card 1 is the auto-save: loadable, never a manual save target. Load starts on the first used box, Save on box 1 of card 1 (box 0 on card 2).
* **Box pictures.** A used box shows the picture of its file's number n (the PS1 number icon, RDE's face icon `hd/menufaceicon/<set>/icon_NN`): a file in the box of its own number shows its own picture; a file in another box (a directory not in number order) shows the cursor box's picture unless cursor + 1 exceeds the largest n drawn, then its own (`save_layout::box_icon`).
* **Saving overlay.** While the saving screen shows, the cursor box gets one more picture over its own: the lowest file number no file of the card uses (card 1's 0 counted as used, so for a new save it is the number being written), chosen by the box rule above with that number counting toward the largest n. A new save therefore shows its file's picture in the empty box it was saved from; an overwrite usually shows the box's own picture again; a card with every number taken draws nothing more. RDE capture (a forged card holding 00 01 02 04 in boxes 0..3, window frames at 1280 x 800): saving from the empty box 5 shows file 03's face there while box 4 stays empty, and the grid reorders (03 in box 3, 04 in box 4) only on the next visit; overwriting box 2 afterwards keeps Guile's face on it. `MainMenu::Impl::do_save`, `build_save`, `save_layout::saving_number` / `saving_icon`.
* **Page list.** 101 rows (0 = the page's auto-save, 1..100), 10 visible (kPageRows). Up / Down wrap one row, Left / Right move 10 rows without wrap. Row 0 is not a save target. The first visit of a session starts Load on the first used row and Save on row 1; after that each of the two comes back on the row and scroll it was left on (`page_memory`), across menu openings, until the game exits. The card grids start over each time.
* **Overwrite confirm.** OK on a used box or row in Save opens Yes / No with the cursor on No (`confirm_cur` 1); any direction toggles; Cancel dismisses. OK on an empty box saves at once. Load asks nothing: OK on a used box or row loads it at once, OK on an empty one is refused (sfx 0x18). RDE capture (Load on card 1, OK on a used box): the screen is black 0.44 s later with no prompt shown, and the picked file's room is entered.
* **Where a save goes.** A used box overwrites its own file. An empty box creates a new file with the lowest unused number from 0..14 (0 is reserved on card 1). With no free number nothing is written (sfx 0x18 only). The card save also writes the `ext_save.dat` record (language, battle counter, custom names; `formats/save.md` section 9) and rewrites the whole `save.dat`. A page save writes the numbered file with the same extras. A full card or write failure shows the failure message and plays sfx 0x18; success goes through phase 4 (the saving screen, then the two save chimes, next bullet but one, and the Save / Load choice). RDE capture (an overwrite of a used box of a forged card, the screen state read every 4 ms and the window captured every 70 ms): the confirm at 0 s, the saving screen until 0.37 s (the game holds the frame while it writes, so the progress bar never shows), then in the same frame the chimes and the Save / Load list with the cursor on Save and "Save a File" below it. The result sets `saved`, which scripted menus return as variable 0x4C = 1.
* **Load.** A picked load sets the load request and closes the menu; the host takes the request (card, slot, block, data) and starts the slot like Continue (fade 0.5 s, then section 13 flow).
* **Faces.** The detail panel's three faces come from the summary's party bytes, which every save (card file, page file, auto-save) writes from the party and each member's model byte (`formats/save.md` section 4): a member whose body is at most 0x31 shows that body's face (Serge as Lynx shows Lynx, Pip his form), otherwise his own; 0xFF and ids above 0x31 show none. The leader's name still follows the party at 0x59C.
* **Load chimes.** Every load (title Continue, the in-game Load, Continue+) plays effect 0x19 (mask 0x20) and effect 0x76 (mask 0x40), centre pan, full volume, in the frame the screen reaches black; both are about 1 s chimes. On the PS1 the field starts 17 frames later, stops the music and ends every sound, which cuts the chimes (title Continue capture: confirm sfx 8 at frame 43, the black fade from frame 94 to 155, both chimes at 155, music stop and end-all at 172). RDE keeps the chimes: the field's first end-all after a load chime stops the music and then waits until the mask 0x40 chime has run out before the field goes on. OpenCross follows RDE: at black the chimes start and the music stops, and the room loads when the 0x40 chime has ended (`GameFlow::tick_fade`; a run without an audio device loads at once). The Save screen plays the same pair once a save has finished (the save state, when its veil has reached full; the save site is not hooked by RDE, so the music goes on). RDE capture (an in-game save over a used box of a forged card, the SFX channels and the stream read every 5 ms): the confirm (effect 8) on two channels, then 0.36 / 0.39 s later 0x76 on mask 0x40 and 0x19 on mask 0x20, while song 40 keeps playing to the end of the run. OpenCross plays both 22 frames after a successful save's confirm (`MainMenu::Impl::end_saving`, on the layer sound hook with their own masks) and leaves the music alone.
* **Location caption.** Keyed by script variable 0 (head byte 0x40, u16): the key is the number of the 30 thresholds `{0, 8, 16, 24, 26, 28, 30, 36, 52, 64, 72, 80, 88, 92, 100, 108, 112, 116, 124, 128, 140, 144, 156, 164, 172, 184, 195, 202, 209, 999}` that the value has reached, at least 1; the caption has two lines.
* **Corrupted data.** A card file whose block fails the checksum (`formats/save.md` section 3) keeps its box and preview; loading it (OK on the title grid or on the in-game Load grid) plays sfx 8 and shows "Save data in Slot 1 is corrupted." / "... Slot 2 ..." in the message frame instead of loading; confirm or 120 frames closes it and returns to the Slot choice (title) or phase 0 (in game), as "No save data" does. Older blocks (version below 0x106) load with the version gates applied. A block that fails structurally (wrong size) is left out of the grid with a warning; a failing file on the title list is likewise skipped. Page files that fail validation are skipped at boot (`formats/save.md` section 13). Directory entries are accepted with a Japanese or US game name and a two-digit number.
* **Title Continue lists.** The choice (OpenCross / Slot 1 / Slot 2) and the page list behave as above. The card grid holds one box per readable file in directory order with no number limit and no auto-save rule; Left / Right wrap over the files, Up / Down jump 8 boxes when that box exists. A file is picked, not confirmed: OK starts the load (fade), Cancel on the grid or page list returns to the choice, Cancel on the choice leaves to the title with the cursor on Continue. An empty target shows "No save data" (120 frames or confirm). Continue+ is section 13.

## 11. Party editors

Source: `game/party_editor.h`, `ui/party_screen.cpp`; flow fallback `game_flow.cpp`.

**Grid** (shared): the recruited characters that are not in the exclusion bitmap (words 2..3 of the lock block, which holds two lock words then two exclusion words), ascending ids, at most 44, 4 columns, 5 visible rows, scroll 0..6 rows. Left / Right wrap over the columns, Up / Down move the row and scroll at the visible edge, sfx 1 on every press including the ends. A scroll takes 17 frames of 2 px; input is ignored meanwhile.

**Party editor** (script party screen / Tele-Porter, 3 slots). Members are packed on entry (empties and duplicates dropped). A member that is not in the grid (excluded) keeps its slot.
* Slot mode: Left / Right wrap over 3 slots. OK on an empty slot, or on a slot whose member is not locked, enters pick mode (sfx 8); a locked member is refused (0x18). Cancel leaves (sfx 6) unless a slot is empty while the number of filled slots differs from the grid size (sfx 0x18).
* Pick mode: OK on a character who is not in the party puts it into the slot (it replaces the slot's member); on a character of another slot swaps the two and moves the slot cursor to that other slot (both sfx 8, the grid stays open; the swap does not test the lock bit, so a locked member can change slot but never leaves the party); on the slot's own character or an empty cell is refused. Cancel returns to slot mode.
* Lock bitmap: bit c of the two lock words means character c's slot cannot be opened for a replacement; the party-screen path passes it, the flow fallback (used when the party screen is unavailable) passes none and lists every recruited character, excluded ones included.
* **Reserve slots** (OpenCross, party swap's `Reserve` setting, `formats/mods.md` section 8; none with `Reserve=0` or the feature off). The help text goes and the Current Party window becomes a panel of two rows in its space: its top is raised, its side lines run down both rows and its top drawn upside down is the bottom edge, labelled Reserve. The reserve row shows 3 slots under the party slots and scrolls sideways past more (arrows on the side with hidden slots). Left / Right wrap within the cursor's row (the reserve row scrolls with the cursor); Up / Down switch rows, keeping the column. OK on a reserve slot enters pick mode for it: a free character fills it, its own character empties it, a character of another reserve slot swaps the two, a party member swaps with the slot's character (refused 0x18 for a locked member). A party slot's pick of a reserve member swaps the two. The cursor follows to the slot the picked character came from (all sfx 8). With the `PartyScreen` feature's `ReturnToSlot` (`formats/mods.md` section 8; off unless a mod or the player turns it on) every pick instead returns to slot mode on the slot it filled, the party slots included. On entry a reserve slot holding a party member, an unavailable character or a repeat is empty. Leaving writes the slots to the save's tail record (`formats/save.md` section 3).
* Leaving compacts the party (empties dropped, order kept). The host writes it to the state (0xFF for empty) and rebinds the party entities and models; the party screen first runs a 0x40-frame closing fade, the fallback closes at once. The field then fades in from black over 0x20 ticks, as after the relief editor (`formats/fieldscript.md`, screen returns).

**Relief editor** (Relief Charm). Grid only. OK on a character other than the current relief member sets it (sfx 8, the screen stays and the cursor stays); on the current relief member or an empty cell sfx 0x18; Cancel always leaves (sfx 6). The relief member cannot be cleared here. The stored member is head byte 0x59F; on entry it is cleared when it is 0x2C or above or not recruited. The cursor starts on cell 0 and the shown character starts as the relief member, else character 0.

**Grand Slam monster picker** (field FE 75 #round + FE 61, zel_a17i). Source: `ui/monster_pick.*` (rules), `ui/monster_pick_screen.*` (screen), `ui/menu/picker_model.*` (creature models); opening and closing: `app/app_sim.cpp`.
* **List.** The Dopplegang pool slots whose bits are set in variables 0x3E0..0x3FE (word w bit n = slot w * 16 + n), ascending, at most 130 (checked after each word, so the last word may add up to two more); 3 per row, 42 rows, 6 visible, 13 px per row. A pool slot is also the monster record and the name index (system text category 0x19).
* **Round table.** 9 list positions (3 per round, 0xFF none), kept for the session. Opening round r clears its entries from r * 3 on, so earlier rounds' creatures stay taken. The three picks start on the first three free list positions (searched among positions 0..128). A position is taken while it is in the round table or one of the current picks; taken names are red, the cursor's name orange, the rest white.
* **Slot mode.** Left / Right wrap over the three picks (sfx 1); confirm opens the list (sfx 8); cancel ends the picker (sfx 8): the picks go into the round table and their pool slots become the battle's party (`rules/battle.md`, monster-party scenes).
* **List mode.** One 60 Hz frame runs two input passes (Left / Right only in the first). Left / Right move over the columns, wrapping column 0 <-> 2 into the previous / next row; Up / Down move the row and at the visible edge scroll the list one row in 13 steps of 1 px, two per frame, ignoring input meanwhile. After a scroll up the step counter rests at -1 (the list 1 px lower) until the next scroll down. Confirm on a free entry makes it the slot's pick (the old pick is free again, sfx 8); on a taken or empty entry sfx 0x18. Cancel returns to slot mode (sfx 8).
* **Layout (320 x 240).** The three picks' creature models sit in the pick boxes (drawn at the table scale; a scale of 0 draws nothing). Pick names start at x 64 + 96 * slot - 6 * n + nudge, y 100, where n is the Japanese name's glyph count (at most 8); the list window (16, 128, 288 x 78) clips its rows, names at x 28 + 96 * column, y 128 + 13 * row + 2. The cursor (5 frames of 8 frames each, 8 x 8 px, 4 px below its point) sits at x 14 + 96 * slot, y 98 in slot mode and at x 16 + 96 * column, y 128 + 13 * row - 2 in the list.
* **Text (RDE, both art modes).** Names are left-aligned in the PC font: the JP font slot (kb) in Japanese, the menu font slot (bn) otherwise, at the slot's scale; colours white 0x757575, cursor orange 0x285085, taken red 0x000075. Outside Japanese a pick name moves by a nudge chosen by its pool slot (-12: 0x02 0x12 0x18 0x1A 0x2F 0x35 0x36 0x38 0x41 0x6C 0x7C 0x8E 0xB2 0xD7 0xD8 0xD9; +6: 0x03 0x20 0x27 0x31 0x4D 0x56 0x5C 0x5E 0x70 0x8F; -6: 0x0A 0x0B 0x0E 0x13 0x14 0x1F 0x29 0x2A 0x3D 0x47 0x5D 0x78 0x79 0x88 0x99 0xAC 0xB5; -18: 0x0D 0x17 0x24 0x46 0x51 0x71 0x89 0x8A 0x8D 0x95 0xA4 0xA5 0xA6 0xB7 0xD6; -24: 0x7E), and a few long names (per language, by pool slot) are drawn at a smaller scale and up to 2 px lower (`kStylesEn..Es`, `kStyleScale` in `monster_pick_screen.cpp`).
* **Backdrop.** The room's background group 1 (the picker's frames) at scroll (0, 0) with group 0 hidden, over the field system texture pack's fifth image tiled 64 x 64 across 640 x 220; closing restores group 0 and the scroll. HD draws the cursor from `hd/menu/monmenu_cur.png`.

## 12. Pause screen

Source: `ui/pause_screen.*`; opening and closing: `app/app_sim.cpp`.

* **Rows.** PAUSE bar; "Vibration Function: On / Off" always; "World Names: On / Off" only when the row condition holds.
* **World Names condition.** The field world is up, script variable 0 (scenario) >= 0x34 and variable 0x50 (map has a world name) is nonzero. The value starts from variable 0x52 != 0 and is written back to variable 0x52 (1 / 0) when the screen closes, only if the row was shown.
* **Input.** Left / Right (or OK) flip Vibration (sfx 1); Up / Down flip World Names when its row is shown (sfx 1). Start (Space / pad Start), Cancel or pad East close it (sfx 6). Vibration is written to options bit 0x400 every frame; switching it on gives a test rumble pulse.
* **Opening.** In the field: Start when `FieldWorld::pause_allowed()` and the menu is closed. Over a running battle: Start at any time except while the battle transition is active. Over a movie: Start. Never over the title scene (logo, attract movies) or the title's own screens (menu, slot list, name entry). The keyboard's Space opens it on the press; the pad's Start opens it on release of a press shorter than 500 ms, a longer press opens the settings window instead. The settings window (RDE's Esc menu) also opens and closes with Esc, on the press, and with the pad chord LT + L3: both down with one of them pressed in this frame, the window toggles one frame later, while the buttons are still held (`game::MenuChord`). As on RDE the chord's LT press also toggles slow mode and its L3 release toggles encounters off, and these pad toggles keep working while the settings window is open.
* **Where pause is refused** (`pause_allowed`): during room init, a room transition or a jump; when the room's pause flag is clear (global flag kPauseAllowed, set at every room load and cleared by script) or the low byte of variable 0x36 is nonzero; on maps 8 and 9; while a menu, movie or battle hand-off is in progress. Open windows, choices, running cutscenes and the input lock do not refuse it.
* **What it freezes.** The pause screen takes all input: the field, battle, results and movie simulation stand still. The play-time counter is advanced before the pause check.
* **Tint.** A counter 0..479 advances by wall time at 60 per second and is kept across openings. `ramp = counter > 0xEF ? 480 - counter : counter`; `t = ramp / 240 * 0.53`; the picture is multiplied by `(1 - t, 0.47, 0.47 + t)`.

## 13. Title screen flow

Source: `game/game_flow.*`, `ui/title/title_screen.cpp`, `nav.h`.

* **Phases.** Fade in, "Press any button" prompt, menu, fade out (0.5 s each). With the title room behind (scene mode) the screen starts at the prompt. Any input (Confirm, Cancel, shoulder buttons, any key except Esc and F1..F12, any pad button except the stick clicks) leaves the prompt through black into the menu. Navigation repeats after 0.4 s every 0.08 s; the left stick past half way counts as the d-pad.
* **Press.** The press plays the chime: global sounds 59, 61 and 62 started together, each on its own field sound slot (0, 1, 2; full volume, centre pan), so none cuts another. The picture holds 22 frames, then a subtractive fade (the picture minus a rising level) reaches black over 32 frames. The music fades out: the fade starts 14 frames after the press, takes 20 frames to reach silence and the song is stopped when it ends. This is the title room's song in scene mode and the title's own song otherwise.
* **Rows.** New Game, Continue, Settings, Quit (Up / Down wrap). Settings reports at once and opens the options window. Quit fades and quits.
* **Continue enabled rule.** The row is enabled when the OpenCross page holds a file or either card holds a readable slot (`SlotList::any`, re-evaluated each time the title is entered). Disabled: sfx 0x18.
* **Back to the prompt.** Cancel on the menu (sfx 6) fades to black and returns to the prompt, which fades in again. The music starts again from its beginning: in scene mode the title room's song (the scene keeps running), otherwise the title's own song. The original's menu has no way back to the prompt; OpenCross keeps one.
* **Vibration page.** New Game opens a page with On and Off (cursor on On; Up / Down toggle). OK stores the choice, reports New Game and fades out; Cancel returns to the row list on row 0. The choice becomes options bit 0x400 of the new game state; Continue never touches the options word.
* **New Game.** After the fade: the user guide (below), then name entry for character 0 (Serge) with the language's default name. A validated name starts a fresh game (Serge, Kid and a random third member from a 14-entry table; gold and stars per `new_game.h`; location room 22), plays movie row 2 and loads `opn_a01i` with room param 0: the room and param of the title script's `MAP_JUMP_DC` (`FieldWorld::script_map_jump`, #22 #0 as shipped), so a mod's `opening.bin` that jumps elsewhere starts there.
* **User guide.** Two pages (controller, then keyboard) of baked images. Shown at every New Game, and on a script name entry (opcode FE 4A) when script variable 6 (MAP_ID) is 0 or 8. Skipped when the page images are missing. A 45-step counter at 60 steps per second runs the fade-in of page 1, a wait, the fade-in of page 2 over it, a wait and the fade-out of page 2 (15 steps each). Each wait ends on any key press except F1..F12, or on the frame the pad goes from some button or stick held to none (stick clicks and Start excluded).
* **Continue.** Slot list (section 10); a pick fades the screen out for 0.5 s and then restores the state: the state is replaced by the slot, the Time Shifter key item is granted, record names that are usable and `ext_save.dat` names (same language only) become the custom names, a name record left empty takes the default (`formats/save.md`, section 7), the location word selects the room (a word of 0 with no room name logs a warning and loads no room; a nonzero id is looked up in the disc index and returns to the title when no room is found), the saved leader position (script variables 0x12, 0x14) is restored and the room parameter is variable 0x3A. Cancel on the choice returns to the title menu with the cursor on Continue.
* **New Game+ variant.** The ending room's script (FE 84 + FE 61) shows variant 2 over the cleared game: rows "New Game +" and "Continue +" only, straight into the menu with no prompt and no cancel. New Game+ goes through the vibration page, then replaces the state in place (carry-over per `formats/save.md` section 14) and the ending script goes on. Continue+ opens the slot list in plus mode: a slot whose two summary flag bits are set (bit 0 completed, bit 1 already New Game+) is refused with sfx 0x18; a pick carries the cleared game into the loaded slot after the fade; the custom names stay those of the cleared game. Cancel on the Continue+ choice returns to the variant 2 list on Continue +.

## 14. Character names

One rule serves every screen (`data::character_name`, `src/data/char_name.h`). A character's own name is its typed name, or the language's `sysmes[0x10000 + id]` when none is set or the language's font cannot draw it (kana outside JP). In JP, battle and the menus add the rank to Viper's name.

Serge (id 0) whose record model byte is 0x31 reads as Lynx, `sysmes[0x10031]` in the game's language, ignoring his typed name. Model bytes 0x3C..0x3E stand for the model held in script variables 0x170..0x174. Only id 0 is special: another character wearing 0x31 keeps its own name. Model byte 0x33, the same body under another byte, keeps his own name on every screen.

| Where | Serge in the Lynx body |
| --- | --- |
| Battle HUD, target label, results, battle messages | Lynx |
| Main menu, status, elements, Current Party | Lynx |
| Dopple list, first row | own name |
| `{PARTYn%}`, `{playwork(n)}` in field text | Lynx, own name while `GF.16` is set |
| `{SERGE%}`, `{SERGE}` | own name |
| Lynx duel | `battle.md`, section 1 |

The save lists (title Continue, Save / Load grid and page) show the saved leader's own name as loading that file would give it: the file's `ext_save.dat` or page name in the game's language, else its record when usable, else the default. The Lynx rule does not apply.

The art follows the body the same way (`data::menu_form`): the portrait strip of the main list, the Elements and Equip screens and the battle results screen, the weapon pack and the profile text show the body when it is at most 0x31, else the character. So Serge in body 0x31 shows Lynx's portrait, Pip his form's, and body 0x33 Serge's own. This holds for any character, unlike the name rule.

## 15. Button panel

RDE adds a panel to one code entry of the story: the machine by the door of the burning orphanage's hall (`kji_b01i`, entity 11), whose script reads the pad with key-latch tests (ops 51 / 54) while the player stands on it and gives Hot Shot for the right four buttons. RDE draws the panel over that room only; OpenCross gets the same through a script correction of the room (`formats/fieldscript.md` section 13) that runs FE D1 before the script's tests (`game::ButtonPanel`, drawn by `FieldWorld::sync_panel_window`). Measured on RDE (field variables of the machine read from memory after each press).

* **Opening.** While the machine reads the pad, a Circle, Cross or Triangle press opens the panel and reaches the script as Circle (a wrong button: the code starts again). Square and the shoulder buttons leave the panel closed and reach the script as pressed (L1 measured); entered with the real buttons, the code therefore cannot use Triangle.
* **Window.** A message window in the player's skin, four lines of two cells: `○ L`, `× R`, `△ B`, `□ Y` (Japanese: `〇` and full-width spaces). The symbols are drawn with the JP message face outside Japanese, each counting a full-width cell. The cursor cell's glyph is orange (text colour 6) with the choice hand before it; the window opens whole, without the grow.
* **Keys.** Up / Down change the row, Left / Right the column, no wrap. While the panel is open the pad reaches neither the player nor the script (the held-key word reads 0).
* **Pick (Circle).** The cell's button goes to the script. The picked cell turns cyan (colour 2) and the cursor stays on it for 60 ticks (1 s), during which the panel takes no key; then the cursor returns to the first cell. Circle column: Circle, Cross, Triangle, Circle (Square delivers Circle). Letter column: L1, R1, Circle, Circle; outside Japanese, from the second pick of an opening on, L delivers Circle and R delivers L1, so the English hint LARA (L, Triangle, R, Triangle) is the code the script's L1 Triangle L1 Triangle wants. A pick waits until the script has read it (OpenCross: a further pick is not taken before; on RDE the pick is offered for a fixed time).
* **Closing.** Cross closes the panel and sends nothing. After the fourth pick of an opening the panel closes once that pick's hold ends; a right code is complete at that pick. A Circle, Cross or Triangle held when the panel closes counts again only after it is released. A room change closes it.
* **Layout against RDE** (640 x 480 capture, cursor on Circle): symbol column x 152-170 (OpenCross 153-170), letter column x 205-215 (202-213), row tops y 94 / 121 / 148 / 176 (93 / 120 / 146 / 172). RDE sizes the window itself, about 9 PS1 pixels wider and 5 lower than the frame OpenCross builds around the text.
